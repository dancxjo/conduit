## Reservations layered below each kernel

1. LocalExpressionFactory derives exact input/output ceilings via `maximum_prepared_input_bytes` and `maximum_prepared_output_bytes`. Per expression its budget adds2 value items, input+output live-byte quota, max(input,output) maximum value,4 Sign items. `PreparedLocalExpressionBack` owns its independently prepared evaluator and exact limits.
2. ChildKernel adds Cord slots/bytes and every factory budget, then calls `HostedValueStore::new(item_capacity, maximum_value_bytes, byte_quota)`. That constructor reserves **every slot at the global maximum value**, regardless of the smaller sum of intended live bytes. Formula per child: backing payload capacity = item_count * max_value; live quota = Cord byte sum + factory input/output sums. Metadata is additional. `reserved_storage_bytes` and `allocation_capacities` explicitly distinguish these quantities. This is a static worst-case rectangular reservation hotspot, not measured usage.
3. PreparedPortableExpressionEvaluator allocates an output Vec for each nested child evaluator. Structured constructors recursively prepare fields; each retains a cloned StructuredInfoType, a canonical type prefix and a child evaluator. Member/sequence selections may additionally own a canonical selected-output buffer, then their enclosing evaluator copies that output into its own buffer, then a parent constructor copies again. Conditional arms are both prepared even though only one executes. Equality/inspection children likewise prepare independent subtree evaluators. Many repeated forwarded large structures can multiply conservative capacity and schema storage across71 gears.
4. Generic byte bounds deliberately overapproximate: Text/Bytes and unknown leaf kinds use the131072-byte leaf ceiling; full frames cap262144. Without an authored input envelope, each expression uses that structural ceiling. With an input bound, provenance-aware expression bounds exist, but each independent field projection may still be charged up to the input bound and constructor sums cap262144. An input bound does not imply equal output size: constructors can duplicate or expand data.
5. Immutable input schema sharing **already exists** via SharedBytes Arc<[u8]> (Rc on non-atomic targets) cloned among prepared children. Proposing to add that sharing would duplicate an existing fix. Other per-child schema/value-type/prefix copies remain separate.
6. KernelCompositeHost owns finite child schedulers, fronts, links, active plays, HostCall obligations and Sign storage. InternalLink reserves transfer bytes from the exact source Cord maximum. Child scheduler uses the existing fixed profile64 nodes,128 Cords,16 ports/node,256 queue slots,1024 route slots,128 total route targets,512 Host Call slots and64 pending request slots even for a small active graph. These are additional finite fixed costs, not necessarily the dominant RSS source. No new scheduler is required or proposed.

Driver-local14 input/output payload buffers are at most14*2*262144 =7MiB under the global frame ceiling. Default evidence arena reservation is32MiB, plus1024 observation records. Those two classes alone cannot numerically account for3.8GiB even if fully resident. The fourteen kernels can contain many more than14 expression Backs; counting only their external buffers misses the nested preparation and plan/schema duplication.

## Existing lawful Source envelope

The supported multiline syntax is:

```conduit
plot bounded-operation (
    input: SomeNativeType...| <= 65536B >> output: ResultType...|
) = (...)
```

This is a real input Fore value contract. `canonical_expansion/structured_selector/input_bound.rs::checked_bound` obtains the original Face input contract or the actual upstream internal gear output contract. It populates `CheckedExpression.input_maximum_bytes`; PortableExpressionProgram serializes Some(bound) as the versioned v3 program header and None retains v2. `semantic_laws` exposes the same input contract. An exact identity may also forward that bound as an output law. Arbitrary transforms cannot inherit an output bound merely because their Type matches the input.

`maximum_prepared_input_bytes` is min(authored envelope, structural ceiling). The output is separately derived by sound expression provenance. LocalExpressionFactory validates the exact program-derived offer, ports, semantic laws and limits against the actual placement; the driver plans each input/output/internal Cord from those exact program bounds. Existing Conduitos expression tests prove a Source <=2048B contract reaches program, Fore, offer, lowered input and actual owner. Publicly mutable Program fields are not authority to rewrite a retained program behind Source/Plan identity.

An outer compound65536B contract does not automatically constrain every named internal helper plot or every expanded constructor output. An unbounded helper can legally retain262144B. The driver's separate65536 transport/evidence profile can refuse a larger request; that does not narrow the already-advertised LocalExpression kernel contract. Do not clamp input_maximum_bytes, queue/offer maxima or backing storage to observed request size. Regenerate actual Source/offer/Plan identities and retain refusal evidence when a computational contract changes.

## Smallest coherent options, in order of semantic scope

**A. Share immutable exact definitions/program/schema data without changing contracts.** A generic shared-definition preparation API could let Operation and KernelCompositeHost retain the same immutable definition/plan bytes (not a second serialized clone), with exact full equality/identity validation preserved. Immutable program/schema interning keyed by actual canonical content can also remove duplicate type/hex storage while retaining distinct per-Back evaluator, staging, sequence/cancellation and mutable output state. This is the lowest semantic-scope option; no Source or numeric bound changes are needed. It still needs explicit accounting to establish saved live bytes; no RSS target is claimed.

**B. Borrow forwarded intermediate values / use a preparation-owned liveness arena.** Retain a single owned final output but let exact input/projection/unchanged-branch intermediates borrow admitted canonical views rather than materialize a full per-child output. Existing selectors already borrow primitive payloads. Computed children retain finite scratch admitted before Play; mutually exclusive branches can share scratch under a proved lifetime/liveness layout. Generic soundness must cover nested frames/type-prefix reconstruction, repeated projections, aliases and constructors, error/conditional paths, equality/inspection, and output ownership until commit. No-growth Play, canonical-byte parity and stable cancellation/pressure behavior remain required. This preserves current Source contracts and is likely broader leverage than a caller clamp, but requires careful evaluator changes.

**C. Derive tighter generic storage ceilings from existing byte provenance.** Improve structural/projection/constructor accounting without changing Program input contracts: e.g. account for disjoint fields and known fixed canonical leaf lengths rather than charging each forwarded field an entire enclosing input. Exact Core ResourceRef has validated maximum512 bytes, but unknown opaque kinds cannot inherit that bound. Repeated field uses genuinely multiply bytes; branches use maxima; raw/nominal framing must be exact. A smaller bound must be proved for every admitted input, not inferred from this fixture. Program meaning stays unchanged, but derived computational Fore/offer limits may change, so exact offers/plans must be regenerated and validated.

**D. Explicitly author a bounded Source profile where semantics intend it.** Add real <=65536B input contracts to relevant individual helper fronts, or an explicitly named bounded profile retaining old general Source. This changes accepted computational inputs/Source identity; it is not a transparent implementation optimization. Prove all admitted intermediate values satisfy those envelopes and preserve larger-input refusal. Fresh full Source, canonical programs, actual host offers, plans and receipts are required. Do not assume all constructors preserve size or use today's small observed payload as proof. This can enable existing provenance bounds and smaller legitimate reservations without changing language decisions, but must remain an explicit reviewed contract.

**E. Heterogeneous HostedValueStore slots only with a lawful allocation proof.** The existing `new_with_slot_capacities` API can reserve smaller per-slot classes, but replacing uniform slots with naive per-Cord/factory capacities is not a drop-in proof. Generic references, overlapping Step transactions, retained values, fan-out, mixed-size occupancy, best-fit fragmentation, generation retirement and pressure must preserve every admitted live workload. Current uniform preparation guarantees each slot can hold any admitted maximum-sized value. A proof-backed owner/class-aware layout or equivalent finite allocator scheme is needed before claiming the same contract; total live byte quota alone does not prove fit. No ad hoc parser-special store or relocation of externally retained ValueRefs is justified.

## Proof and attribution needed before selecting a larger rewrite

Add preparation-time/read-only accounting, not an inference benchmark: sum actual retained definition/program/schema bytes; each evaluator subtree's root/child/selector/branch capacities; per-child value-store item/max/live/reserved quantities; Sign capacity; scheduler fixed storage; transfer buffers; driver/cursor/evidence arenas; temporary preparation high-water separately. Existing ValueStore accounting and `internal_transfer_capacities` are reusable; recursive evaluator and child summaries need a small generic inspection API. The inspection can return fixed counters without allocating during Play.

For any selected change, reuse ordinary Source/local Back/composite tests: byte-identical results, exact expected Fore/Plan laws, refused oversized/malformed inputs, cancellation and pressured output preservation, shared immutable preparation with independent mutable lifecycle, and allocation probes around actual Play. Static reservations can be compared before/after preparation; a whole-fixture RSS sample remains separately scoped. No build/test/benchmark/cache operation was performed for this audit.
