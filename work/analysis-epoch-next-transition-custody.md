## Why accepting a selected transition alone is insufficient

Current private owner starts with Source-authored initial beam. Existing
language-parser-scorer-selected-transition legally executes one caller-proposed
class/score, but accepting it as a beam replacement would let callers omit other
live survivors/branches. Native beam admission and one legal transition prove
neither the declared beam4 search profile nor that all private candidates survived
until actual checked merge/rank. Therefore no arbitrary update(beam), digest, best
state, selected transition or vector of caller-chosen successors is acceptable.

## Minimal complete round, not a new runtime

NEW PreparedAnalysisRoundProgram prepares existing Source expressions once and
replays the same bounded actual observations as the installed target execution.
NEW PreparedAnalysisRound is opaque, borrowing/retaining exact source/generation,
full prior beam and lexical snapshot, policy/model profile, ordered frames for all
required operations, complete actual final beam and actual refusal history.
Preparation is invoked through &AnalysisEpochOwner so prior/generation are copied
privately, never supplied by caller. Token/slot/class enumeration is a declared
finite protocol schedule, not Rust legality/ranking. Requests and next phase must
be derived from actual Source output. Failures preserve owner and all trace frames.

Use the existing test driver's declared finite round profile, not copied kernel
code: all FOUR prior slots, all admitted lexical alternatives (<=4) where Source
branch requires them, five existing action legality representatives per active
prior, existing feature Source, ranking mask/next-best selection, all <=4 selected
classes per branch, actual selected-transition Source and Source merge. Source
owns branch acceptance, legality, transition/refusal, feature extraction,
score rank and insertion order. Owner checks trace completeness/correspondence to
the fixed schedule so no active slot or accepted branch can silently disappear.
No early root/comma locking, caller-pruned candidates or best-only rebase.

A declarative checked full-round composite or replay wrapper may reuse existing
expression programs and ordered typed frames. It must not handcode transition,
score, agreement or rank arithmetic. Existing selected-transition public Source
has Zip/transition/expand topology; ordered replay can reuse actual existing
parser transition stages plus scoring expansion, just like commitment replay,
while its installed target Plan independently supplies execution custody.

Exact Type bridge: use existing LanguageParserScorerBranch, BranchResult,
ChoiceQuery/Features, ScorerLegality/Ranking, ScoredClass, Selected,
ScorerRawHypothesis/ScorerMerge/Beam and generated owner validators. Refined
outputs are field-copy-admitted through Native constructors after raw Source
execution. Do not construct refined Types dynamically in pure Source or relax
CND-FRM046 to make the composition fit.

existing Source fallback/ranking owns policy; no caller score array accepted.
