# Proposer-backed Window8 numerical candidate

This candidate uses 446 categories, 27 lookups and 76 classes. It preserves the legacy 425/25 model. It is not installed in a production profile or accepted by a public Session.

Supervision is pinned UD English EWT TRAIN plus 22 explicitly analyst-authored teaching rows. The eight original authored evaluation cases are now training diagnostics for this candidate. DEV and TEST were not used to fit or select it. EWT is UD 2.18, commit b7711cce01cdd4f5fcc0a8199b8a50d951b16c0c, licensed CC BY-SA 4.0; see https://github.com/UniversalDependencies/UD_English-EWT . Corpus bytes remain external and are pinned in the manifest.

The dictionary contains 8,192 entries across 128 shards, with at most four alternatives. All alternative omissions are preserved. Canonical shards passed the complete original Native family admission. Candidate lemmas copy surfaces up to 128 UTF-8 bytes; longer surfaces use the explicit `<unlemmatized>` marker. This is a representation policy, not a lemma truth claim. Unknown candidates remain ADJ/NOUN/PROPN/VERB proposals with original unknown provenance and stable-input-consensus policy. The first training set contains no unknown-origin examples.

The model artifact SHA-256 is 2732ce2c0956d1ec83eafa5fe615dc559a10106d6fd781f58074d2ccc331c9af. Full expected signature, artifact/reference, canonical proposer definition, unknown policy, numerical Types and Source contract digests are archived independently of any adopted scorer. They are candidate metadata, not closed-factory authority.

Numerical training took 1.08 seconds and 14,516 KiB maximum RSS. Teacher-forced legal-class diagnostics scored 210/212 steps. The external free-running arithmetic diagnostic completed 22/22 rows with 5/22 exact full graphs and POS. It selected the initial vocative and object contrasts correctly but retains punctuation and nominal old-man errors. These diagnostics do not prove original Source execution, Native parser output, streaming stability or heldout accuracy.

Tools are archived byte-for-byte from `work/lexical-proposer-next`; their original paths intentionally remain visible. To reproduce, stage these files under that work directory in the repository, supply the exact pinned external TRAIN file, run the dictionary exporter and extraction into fresh directories, compile `train_categorical_window8.rs`, then train for 12 epochs. Do not overwrite original receipts. The extraction manifest preserves one eligible TRAIN exclusion. `checkpoint-files.json` pins every archived input/output; `proposal-446-training-v2/manifest.json` records training and resource limits. Future runtime acceptance requires the distinct Source ABI, full independently pinned model declaration, bounded model/lexical custody and fresh full Native admissions.
