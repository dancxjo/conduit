# Exact-Type Native record access

The prepared family owns finite record field recipes borrowing complete static original Type bytes. Full Type comparison precedes every field lookup; the recipe delimits value extents of already validated immutable views. It grants no Native/law admission. Every original contract and law remains in its original order and is evaluated freshly. Generated record fields retain constructor order. Nested paths keep the original traversal.

Core preflight validates complete Type bytes without allocation and reports exact recipe Vec request/retention. One-under refuses before recipe allocation. Family preparation charges recipe storage and inline owners in its existing preparation/retention receipt. It does not add a whole-family allocation-free admission operation.

The allocator gate covers exact requests, zero-allocation one-under and foreign Type refusals, nominal identity, and empty/partial/full sequences. Original contract first refusals, generated full recursive/child-capability parity, original imported metadata guards, and family external edges pass. Scoped Core/Plot Clippy passes.
