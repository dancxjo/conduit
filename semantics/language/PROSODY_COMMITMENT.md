# Bounded committed-discourse prosody

`dependency_commitment.conduit` owns the generic exact join from an admitted
canonical dependency arc to every active hypothesis's committed edge.
`PreparedCommittedDependency` and its opaque replay evidence are shared by
pronunciation, translation and prosody consumers; they do not define a second
vocative-specific commitment engine. `prosody_commitment.conduit` then joins
that generic dependency receipt to the exact vocative discourse fact.
`PreparedCommittedProsody::prepare` first replays the existing opaque eight-stage
`PreparedParserCommitment`; a supplied expected result or accepted Boolean cannot
publish this Rust receipt. The Source admission checks source, analysis,
dependent occurrence, governor occurrence, agreed head/relation and coverage by
the replayed committed prefix. Initial profile: at most four tokens, token or ROOT governor, and any
universal relation without subtype. Vocative discourse still requires a token
governor under its existing owner law. Subtypes refuse;
they are not erased. Fixture graphs are explicitly supplied admitted symbolic
graphs, not trained parser accuracy.

`LanguageProsodySymbolicProfile` supplies duration (neutral/lengthen/shorten),
rate (neutral/slower/faster) and focus intent alongside existing symbolic
boundary/prominence/pitch. These are reviewed authored choices, with no sample
rate, milliseconds, acoustic pitch value or vocoder coefficients. The rich
plot selects them from the exact profile; the checked Source frontier operation
also owns pressure/cancel/stable admission policy; the existing fallback remains a
separate heuristic variant. This is a deliberately small single-occurrence
profile, not full general phrasing or a new discourse inference engine.

`ProsodySession` owns one bounded current prosody epoch through the existing
core `RevisionJournal`. Its private journal admits explicit proposal,
replacement, stability, commitment and correction events. Stale proposal
references refuse. Pressure/cancellation preserve all history and frontiers.
Commitment requires stability. Replacement behind commitment refuses; explicit
corrections append evidence and do not change the retained committed plan or
commitment cursor. They invalidate prior stability evidence under the shared
revision law. Historical events retain rich versus heuristic classification.

Authority limit: this session owns **current prosody within its epoch**. The
preparation receipt is not an installed upstream parser-currentness attestation.
An external consumer must correlate the exact source/analysis/commitment with its
own currently installed Language authority before playback. There is no caller
`current=true` flag. This library does not authenticate a physical playback
receipt; its immutable committed prefix cannot be represented as proof that
samples were actually heard. The installed current-parser ingress and eventual
playback-owner receipt remain explicit integration seams for #4907/#5755.

The retained learned `Hello, Travis.` demonstration in `SCORER_SELECTION.md`
still disagrees on the earlier comma. Its contiguous commitment stops after
Hello, leaving Travis/addressee a candidate. The new admission refuses that
prefix; tests do not force commitment or relabel the demonstration. Positive
punctuation and three-placement tests use supplied committed graphs and ordinary
checked Source Plan/Play. Actual learned committed greeting and downstream
compact/FARGAN realization remain separate acceptance obligations.

Adding these Language Source contracts changes the concatenated owner Source
identity even if existing commitment programs remain identical. Refresh exact
carrier/public-artifact custody once the contract is stable; preserve previous
producer/history and compare Source identities separately from program/PCM
identity. This document is implementation scope, not an acceptance receipt.

For that bounded refresh, `cargo xtask prove journey native-speech

producer and independently reloads its retained bytes in a fresh process.
This does not replace broader conformance or required exact-head CI. Reuse
unchanged authoring, playback and footprint proof at their recorded revisions.

## Actual Source execution and shared analysis authority

The public optional `dependency_commitment_execution.conduit` operation
`language/commit-dependency` projects a small original context (arc, basis,
head, through cursor and four hypothesis IDs) to existing finite Zip and runs
`language-parser-beam-commit` on the other branch. It joins the actual output
into a raw `LanguageDependencyExecutionObservation`. Canonical Native admission
then applies the `LanguageDependencyExecutionResult` Source laws for acceptance,
exact basis, frontier, hypothesis IDs and the selected edge across active hypotheses.
Original full Query/Admission, replay programs and complete lexical snapshot
remain on the opaque Rust receipt used by current-analysis authority; the
public join does not redundantly transport a second full Native beam.

The internal `language/committed-dependency-evidence` operation checks fully
correlated data; it is not itself an execution attestation. The optional public
Source must be specialized for Context (5120B) and actual CommitResult (30720B).
`committed_dependency_execution_pair()` computes its complete typed envelope
and refuses a value above the existing generic Zip 65536B pair limit before
package preparation. No generic transport limit was raised. The public original
Query remains independently bounded to 65536B. The opaque preparation permits
Query up to 65536B and Result up to 30720B while `execution_context()` separately checks the
narrower public context/result envelope; the underlying eight-stage replay
retains its own 65536B stage bound. These are different profile boundaries.

The tests prepare immutable packaged Source once per test, then use fresh
normal kernel/Plan instances. A cheap type-only envelope check precedes the
expensive package check. Positive public execution compares its actual
arc/result/context with the opaque replay receipt and checks actual packet
bounds. Serialized execution-result data alone does not authenticate installed
execution or currentness; the public operation's topology supplies the actual
Source execution path, and the owning session supplies current authority.

`analysis_session::AnalysisSession` now supplies the shared authoritative
analysis journal over `DependencyRevisions`. Its current proposal is private;
committing it requires the opaque replayed dependency receipt to match that
exact current arc, source material, prior frontier and stable/actual committed
frontier. The borrowed `CurrentCommittedDependency` ties consumers to this
session and prevents mutating it while they use the authority. Rich prosody
proposal/stability/commit operations require this borrowed authority; merely
preparing a receipt cannot enter as current rich prosody. Existing generic
revision law still owns sequence, history, corrections and pressure/refusal
preservation. Consumers such as pronunciation/translation can reuse the same
analysis authority rather than create another currentness journal.

This authority is real session state, not an assertion about an unrelated
external parser service. An installed application must retain and use the same
owning session at ingress, then connect the resulting immutable prosody to the
existing selected audio/play owner. No independent physical playback receipt
is minted by Language. Root consumer integration owns exact Plan/Play/PCM and
playback-owner correlation; fake-backend evidence remains classified.


The transport profile constants live in `dependency_commitment.rs`; packaged
Source headers and test Zip specializations derive from those same constants.
Measured Native query/type floors require the 65536B public Query boundary
(which never enters Zip), 5120B context and 30720B actual result; the exact typed
pair envelope remains below the unchanged 65536B generic limit. Bounds are
checked against canonical Native packets including their Type schemas, not
just leaf payload. This does not change Source legality or commitment policy.

The hosted test fixture admits each selected Back's advertised finite queues;
it does not establish the ConduitOS convenience protocol's 4096B Fore capacity.
The complete rich admission retains both query and result, and its bare Native
Type schema alone is 76853B. It uses the existing generic pure-expression
profile separately and never enters the narrower Zip pair. No generic capacity
was increased to admit it.


The public `language/commit-dependency` topology emits a raw
`LanguageDependencyExecutionObservation`: its context comes from the original
query, and its actual result comes from checked eight-stage commitment through
Zip. The observation itself claims no admission. Dynamic pure construction of
cross-field-refined Native Types is deliberately refused by the general checker.
The generated `LanguageDependencyExecutionResult::new` executes all retained
Source-owned correlation laws at the canonical Native boundary. The opaque
receipt's `admit_execution_observation` additionally requires the entire context
and actual result to equal its own exact replay, then runs the checked Source
`language/dependency-execution-evidence` projection to expose the admitted arc.
A serialized observation or refined result alone authenticates neither installed
execution nor currentness. The actual public Plan/Play path supplies execution
proof; the shared owning analysis session supplies current authority. Tests
exercise that complete boundary and separately refuse forged correlation and a
validly correlated observation with a different numerical result.

A dependency changes its dependent occurrence while observing both endpoints.
The shared journal's default `observation_end` remains the changed region's end;
Language extends it through a referenced governor when needed. This context
counts against the admitted revisable window and can support a stable frontier,
but grants no commitment. Correction containment and committed-prefix protection
still use only the changed dependent region. Exact Source commitment and live
analysis authority remain separate requirements.
