# Two browser Hosts

Suppose one small computation wants to use two machines: one has the source and another can present the result. The usual response is to split the idea into a client program, a server program, and networking knowledge that both sides must carry.

## Conduit idea

Keep one Form. Let the planner place its Gears on current Hosts and realize the typed Cord over one admitted finite Line. Placement and transport are answers about today's machinery, not authored meaning.

```conduit run two-host
form hello-across {
    message: text/literal("hello across one planned Cord")
    show: presentation/text
    message > show
}
```

## What the run proves

Run the unchanged Form. The source executes on Host A, presentation executes on an independently initialized Host B, and one exact value crosses their planned one-item browser-memory Line. The Form names neither Host, Boot, DOM, address, socket, nor transport.

Look what just happened. The Form did not become a client program and a server program. We did not add networking to it or write a browser version and a second-machine version. We described one computation, and Conduit made two Host incarnations into the machine that performed it.

## Payoff

This is the central Conduit proposition in miniature: one computer can be assembled from multiple computers without rewriting the program as separate platform-specific applications. This demonstration proves two browser Hosts and a browser-memory Line; it does not claim an external network or physical machine that was not observed.

# Plans and Plays

Even when meaning remains stable, today's answer may not. A Host can be busy, a Line can disappear, or a different collection of machinery can become available. Baking today's placement into the program makes every such change a rewrite.

## Conduit idea

The Form captures enduring meaning. An immutable Plan is one exact finite answer for the current Body, offers, identities, resources, and Lines. A Play executes that answer; changed circumstances require another Plan rather than silently editing the old one.

```conduit run two-host plan
form hello-across {
    message: text/literal("hello across one planned Cord")
    show: presentation/text
    message > show
}
```

## What the run proves

Run the same Form and read the compact Plan projection. It seals two exact Host/Boot placements, two fragments, one typed cross-Host Cord, and finite Line bounds. Open the raw evidence for the complete immutable Plan; both views come from the same planner result.

## Payoff

The Plan is a replaceable answer to current circumstances, while the Form remains the durable question. A different machine, load, Line, or placement can call for a new answer without changing what the program means.
