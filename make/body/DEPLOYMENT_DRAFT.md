# New-Body deployment review

`DeploymentDraft` wraps the existing Birth draft and checked Body construction.
It owns naming/Plot edits, the declared first Host, first-only/all-host output
scope and reviewed-release/source-build intent. Target/profile and Host-name
changes replace checked construction; existing make validators own validation.
The existing zero-Body `creche.birth` action cannot bypass deployment review.

A review binds the name and workset, exact checked Host profiles, construction
identity, first Host, output scope, image-source choice and package-derived
make selections. A recipe path or coincident revision alone is insufficient.
Changes reject an obsolete review; package changes refuse rather than silently
selecting another builder. Preparing consumes the encounter and calls ordinary
shared birth once, then binds construction to that Body identity. First-only
selection leaves other declared Hosts available for later preparation.

`PreparedDeployment` retains one biography and selected Host names. It is input
to actual artifact preparation, not an artifact receipt. Target builders must
consume its existing Body identity and biography, with separate exact Host
provisioning. They must not rerun birth per image or count intended parts as
live membership.

This transaction does not execute a Crèche Plot, project native Face, acquire
source/toolchains/releases, manufacture media, or perform carrier effects.
Those production consumers remain #6458 work. Build intent does not authorize
a process or network acquisition, and review does not claim an image exists.


`DeploymentEncounter` now projects Body, Hosts and Make pages as canonical
Faces over an actual producing Body/Plot/Plan basis. It reuses Birth naming
and Plot controls. Every interaction is checked against the current owner
Face and acknowledged Mask Show before mutation. Host-name/profile edits
revalidate construction; changing a target selects that package's default
media kind. Offered checked recipes are finite (at most 64); ambiguous
configuration identities refuse instead of choosing by load order.

The final action returns an exact review for the owning make operation. It
cannot claim an image was built. Its checked/planned Mask test fixture
acknowledges output explicitly for interaction conformance only; it establishes
no native rendering or physical effect proof. The production ordinary Plot,
Host operation and native rendering consumer remain to be wired.
