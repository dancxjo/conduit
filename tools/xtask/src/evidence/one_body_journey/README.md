# One Body journey publication input

`cargo xtask prove render-one-body-journey --evidence-root RUN --output NEW_DIRECTORY --commit EXACT_SHA` verifies and renders one complete #4807 documentary. `NEW_DIRECTORY` must not exist. The command does not add a gallery card or publish a route; the integration owner can do that only after a real producer run has passed this gate and the release train accepts the same source.

The producer must retain a complete `conduit.evidence-manifest/v1` with proof `journey-one-body-five-masks`, suite `journey-gallery`, exact `git_commit`, and every file declared as a required output. All output provenance `scenario_id` values equal one run ID. The manifest's output with ID `journey` contains `conduit.journey/one-body-five-masks@1` JSON: `source_commit`, `run_id`, `body_id`, and exactly eight ordered chapters with IDs `birth`, `join`, `start`, `see`, `hear`, `loss`, `return`, `lull`. Every chapter carries a title, intention, action, result, why, next step, at least one media item, explicit limitations, and a `receipt_id`. Media items name `output_id`, `receipt_id`, and useful `alt` text. This is user-facing copy authored from the actual sequence, not generic boilerplate.

Each chapter receipt is `conduit.journey/chapter-receipt@1` JSON with the same source/run/Body/chapter, a nonempty list of unique action IDs, resulting Face revision, and `outcome: "completed"`. Each media capture receipt is `conduit.journey/capture-receipt@1` JSON with the same identities, one chapter action ID, the same resulting Face revision, media output ID and SHA-256, and `capture_source` (`chromium`, `qmp`, `terminal`, or `runtime-speech`). All JSON files are `machine-readable-manifest` evidence outputs with media type `application/json`.

Media requirements:

- Screenshots are `screenshot` outputs with `image/png` and a Chromium or QMP capture receipt. The resulting page needs at least one of each.
- Terminal captures are UTF-8 `console-transcript` outputs with `text/plain; charset=utf-8` and a terminal capture receipt. The page shows a bounded excerpt and links the complete capture.
- Speech is structurally valid PCM16 `audio/wav` with nonzero sample bytes and a runtime-speech capture receipt. That receipt also carries `show_id`, `plan_id`, `play_id`, exact `voice_id`, `transcript_id`, `transcript_sha256`, and `speech_mode` (`direct` or `llm-assisted`). Its `conduit.journey/speech-transcript@1` JSON repeats source/run/Body/chapter, Show and Face revision and the exact spoken `text`. The `hear` chapter must contain both speech modes.
- LLM-assisted speech additionally records exact `provider_id`, `model_id`, `validation_id`, and `original_model_output` in the speech transcript. The `conduit.journey/model-validation@1` JSON repeats source/run/Body, Show, Face, provider and model; it sets `accepted: true` and carries SHA-256 of both original model output and validated spoken text. This retains model wording and recorded validation without replacing the actual runtime audio.

The renderer checks digest and size of every declared output, refuses undeclared or symlinked inputs, rejects mixed or stale run/Body/Face/action/media relationships, checks WAV structure, and escapes all human text before embedding it in the common site theme. Its checks establish internal documentary correlation. Only the live producer and environment-specific acceptance can establish that the claimed action, Mask Show, QMP frame, browser interaction, speech playback, and human listening actually occurred. Synthetic fixtures in `tests.rs` exercise rejection and layout; they are not publication evidence.

The retained bundle permits at most 128 declared outputs, each at most 16 MiB, and the renderer additionally refuses more than 128 MiB of declared output bytes in total. Previously retained 64-output manifests remain verifiable. The final site staging must measure the actual produced bundle and keep the documentary source commit distinct from the later site carrier commit.

## One live spoken chapter producer

It creates an ordinary **terminal** Mask Show, requests a mechanical `ReadAll` of that exact Face/Show, and sends each bounded batch of committed Tongues segments through a real streamed speech Plan/Play to a digest-bound WAV. Its retained terminal frame, source Show/Plan, ordered segment texts and reasons, speech Plan/Play/Host/Boot, transcript, batch receipts, and completed turn correlation identify what was produced. The speech Plot does not yet produce its own direct spoken Mask Show, and no owner-sealed spoken Mask route or wardrobe selection is claimed. It also does **not** claim selected-speaker playback or human hearing.

Both modes require a clean exact source tree, verify the installed Host release record names that same source, Host, and executable, hash that executable, and check the same Face, Host Boot, and release again after speech Play. Only the nonsecret release identity fields are retained. `--run-id TOKEN --action-id TOKEN` lets a capture owner assign common run and distinct chapter-action identities *before* this action executes; the action token is required when a run token is supplied. Without them, the producer assigns new standalone tokens. A later assembler must not rewrite another run's receipts to make them appear correlated.

The model-assisted mode retains the original model output, exact finite-wording request and validation, model and speech receipts, human-readable transcript, renderer-compatible transcript and model-validation JSON, and a digest-bound WAV. Its receipt distinguishes the installed Body Host/Boot from the local model proof Host/Boot and records the spoken Mask's exact Show, Plan, Play, and artifact identity. A deterministic HTTP fixture remains `diagnostic-incomplete`; even live model inference and an acknowledged WAV do not prove speaker playback or human hearing. Together the two modes supply the `hear` chapter's direct and LLM-assisted produced audio. Their local Mask Plans do not establish an owner-sealed Body Mask route or wardrobe transition. The full eight-chapter page still needs one captured run with actual birth, join, start, see, hear, loss, return, and lull actions, owner-sealed Mask routes and wardrobe receipts, current Chromium and QMP images, terminal captures, selected-speaker playback if claimed, and producer-owned capture receipts under the shared run ID.
