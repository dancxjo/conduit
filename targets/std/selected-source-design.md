# Selected native Source execution

The first seam reuses installed execution's actual remote Cord offer. An opaque,
borrowed `CommittedForeValue` is minted only by that installed scheduler path.
It refers to the existing immutable Fragment, actual child Play, sealed Fore,
numeric Cord/endpoint and offered sequence/bytes. Preparation verifies the exact
producer placement and port; per-port sequence state rejects replay. Witnesses
copy neither Source metadata nor values. The old public `ExternalForeDelivery`
remains an effect request and cannot construct this evidence. Legacy adapters
retain their existing Value/Flow behavior through a default method.

Commit evidence alone supplies no native authority. The next seam retains the
actual initialized provider, BaseRegistry entry and native worker across child
Plays. A selected child receives one capability issued from that actual Base,
with exact grant/resource/current Host/Boot/provider generation. Only the existing
BoundBaseOperation authorization path executes the read. The environmental
wrapper borrows the retained provider, preserving its physical session and source
counter baseline; child retirement never reopens USB or resets continuity.

The provider's bounded capture runs on an independently admitted worker with one
command/result slot and an explicit stack/memory/time bound. Pending completion
must use the existing correlated HostCall lifecycle; no synchronous 31-second
capture belongs in the shared Mask loop. Cancellation preserves affine owners
until actual quiescence. Refusal returns owners instead of dropping the session.

The product combines the independently selected Source owner and opaque committed
Fore witness, verifies exact scope/edge/sequence, then crosses one documented
trusted-native runtime boundary. There is no safe DTO-to-publication constructor,
environment-specific std Back, observer-derived authority or invented MCU Boot.

Proof sequence: public installed Cord/commit witness; compile-fail public-delivery
upgrade; selected Source/grant/registry negative tests; retained provider and
Pending interruption tests; exact environmental typed committed Face. Physical
Green acquisition requires separate Root review. None of these fixture proofs
claims installed Body admission or durable recorder commitment.

## First installed native entrance: immediate CPU proof

`NativeSourceDefinition` retains an independently selected Kind, executable
artifact, one ready Base entry, current grant, checked configuration and finite
request/result/resource bounds. `StdHost::install_immediate_native_source` is an
unsafe native initialization boundary: the operator must establish the actual
owner/definition correspondence and independent authorization. The callback and
received Plan cannot mint a grant. Installation clones/prepares registry,
advertisement and ledger transactionally while idle, then transfers the affine
owner into a single retained slot. Refusal returns both owner and definition.
Replacing that slot is refused until a real retirement path is supplied.

The ordinary installed runner resolves support and storage budgeting against
this retained definition, reserves through its actual resource ledger, binds the
actual next ActivePlay, checks the current registry/provider generation and
exact grant, and issues one scoped capability from independent retained truth.
The shared selected-operation checker verifies exact Kind, numeric lowering,
Host Call, configuration and limits. One BoundBaseOperation performs the sole
authorize/complete lifecycle. An ordinary HostCallBack sends the result through
the kernel Cord; only the existing post-commit Fore entrance can mint the opaque
committed witness. The provider remains in the Host across child Plays.

This first provider interface permits only immediate bounded CPU work: no IO,
sleep, allocation, unwinding, pending worker or retained request borrows. Each
prepared Play has one request/result slot and one operation. It is a proof of
the real installed Source/authority/Cord/commit route, not admission for a USB
sensor. A physical source still requires separately declared native worker stack,
request/result/time backing, nonblocking polling, observed quiescence and
cancellation/retirement. The existing retained SourceContinuity rules still
apply on that owned physical session. A diagnostic response cannot establish
MCU membership, Boot, acquisition freshness or recording authority.

The environmental fixture uses the actual authored Source catalog, bare Empty
input, canonical compact observation, current independent grant and exact
initialized provider. The committed bytes retain producing Host/Boot/Play and
Host-observed time alongside source counter and explicitly unauthenticated
source-reported milliseconds. No per-reading unit/schema metadata or invented
MCU Boot is added. A committed Fore witness by itself is not yet an installed
Body or a durable environmental recorder.

## Retained one-slot native IO worker: CPU qualification

`install_native_source_worker` stages the actual registry, advertisement and
resource ledger, then reserves independently configured Base memory before
allocating buffers or spawning. An affine reservation remains with the Base
between child Plays. Children reserve only their existing Source session. The
Linux native profile charges fixed input/result backing, an explicit control
allowance and a stack-mapping ceiling; startup observes actual pthread stack and
guard sizes and refuses an exceeded ceiling. This is not whole-process RAM
accounting or a claim that requested stack size equals the OS mapping.

One retained thread accepts one correlated request. Installed execution polls
without blocking other Backs. Cancellation suppresses publication immediately,
but completion and resource retirement wait for the actual native return. A
late value is discarded. A provider that ignores cancellation holds cleanup and
backing rather than acquiring a fictitious quiescence result. Base retirement
joins the thread before releasing memory and returning the owner. Startup
refusal returns the original owner; replacement remains refused while live.

Adding the first Body-context capability between child Plays stages a new
offer/ledger generation with identical Base and resource offers. The existing
affine backing token and its reservation transfer together; the worker is not
stopped, released or reinitialized. Any active child reservation refuses that
refresh. Updating an already installed context does not change the offer.

The owning environmental fixture proves timed kernel Back progress during a
pending CPU provider, reuse across two child Plays, late-result suppression,
stubborn-provider custody and insufficient independently offered memory. These
tests use no USB. Physical acquisition, its retained continuity guard, ordinary
environmental publication/Face installation and actual Body admission remain
separate acceptance steps.
