# Committed external Fore evidence

Ordinary installed execution mints a borrowed `CommittedForeValue` only after
its actual scheduler exposes a committed remote Cord offer. Preparation pins the
exact immutable Fragment, current child Play, sealed output Fore, producer port
and lowered numeric Cord/endpoint. Each output tracks the next sequence; replay,
regression and exhaustion refuse before another witness can be minted.

The witness is affine and callback-borrowed. It copies neither Source metadata
nor payload and cannot outlive the actual execution callback. Its public scope
is inspectable; neither those descriptions nor an old `ExternalForeDelivery`
can construct commit evidence. The legacy delivery object remains an effect
request. Default dispatch preserves the existing Value and Flow adapter hooks.

Commit evidence grants no Base possession, Host Call, Body membership, native
resource use or durable recording. A consumer still needs independently admitted
execution/effect authority and must validate its expected scope, edge and replay
state. This hosted contract is not constrained native Fore assignment, MCU
installation, display construction, Root workspace admission or physical proof.

Owning checks exercise actual installed Source-to-Cord execution, pre-commit
cancellation, recurring Flow and legacy dispatch, plus same-Host child-Play
identity separation. Compile-fail contracts reject delivery-to-evidence upgrades,
affine duplication and retaining a witness beyond its actual lifetime.

## Independently initialized immediate native Source

`NativeSourceDefinition` retains an independently selected Kind, executable,
ready Base entry, current grant, checked configuration and finite call/resource
bounds. Unsafe installation establishes actual native owner correspondence;
neither a received Plan nor an observer receipt supplies authorization. Registry,
advertisement and resource-ledger changes are staged transactionally while idle.
Refusal returns the original affine owner and definition, and replacing a live
owner is refused. The owner persists across child Plays.

Ordinary installed planning support and storage admission use this independently
retained definition. Preparation checks current registry/provider generation,
Host/Boot/offer, exact Base/resource/grant and configured operation contract before
issuing one scoped capability. One BoundBaseOperation is the sole authorizer and
completion owner. The ordinary HostCallBack feeds the result through the actual
kernel Cord; only the committed-Fore path can mint commit evidence.

The immediate provider contract remains CPU-only: no IO, sleep, allocation,
unwinding or retained borrows. The separately admitted worker below owns
pending IO and its actual backing; neither interface supplies Body membership.

## Retained one-slot native IO worker: CPU qualification

`install_native_source_worker` stages the actual registry, advertisement and
resource ledger, then reserves independently configured Base memory before
allocating buffers or spawning. An affine reservation remains with the Base
between child Plays. Children reserve only their existing Source session. The
Linux native profile charges fixed input/result backing, an explicit control
allowance and a stack-mapping ceiling; startup observes actual pthread stack and
guard sizes and refuses an exceeded ceiling. This is not whole-process RAM
accounting or a claim that requested stack size equals the OS mapping.

One retained thread accepts one correlated request. Installed execution polls
without blocking other Backs. Cancellation suppresses publication immediately,
but completion and resource retirement wait for the actual native return. A
late value is discarded. A provider that ignores cancellation holds cleanup and
backing rather than acquiring a fictitious quiescence result. Base retirement
joins the thread before releasing memory and returning the owner. Startup
refusal returns the original owner; replacement remains refused while live.

Adding the first Body-context capability between child Plays stages a new
offer/ledger generation with identical Base and resource offers. The existing
affine backing token and its reservation transfer together; the worker is not
stopped, released or reinitialized. Any active child reservation refuses that
refresh. Updating an already installed context does not change the offer.

The owning generic installed-Source fixture exercises timed kernel Back progress during a
pending CPU provider, reuse across two child Plays, late-result suppression,
stubborn-provider custody and insufficient independently offered memory. These
tests use no USB. Physical acquisition, its retained continuity guard, ordinary
environmental publication/Face installation and actual Body admission remain
separate acceptance steps.
