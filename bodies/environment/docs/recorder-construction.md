# Recorder construction

This describes the prepared software contracts. The real browser recorder,
its durable catalog seed custody, Line and Body installation remain incomplete.
The public conformance entrance is `cargo xtask prove environment recording`.
The catalog seed's checked meaning has a separate focused entrance,
`cargo xtask prove environment catalog-seed`.
The browser publication boundary is checked separately with
`cargo xtask prove environment recording-storage`.
The actual IndexedDB boundary has a separate focused entrance:
`cargo xtask prove environment recording-browser` (pinned Chromium required).
It produces artifacts under `target/environment-recording-browser` and retains
browser failure traces under `proof/browser/test-results/environment-recording`.

## Preparation before sampling

The Linux publication owner can prepare an empty selected generation with
`prepare_streaming`. Kernel tables, value/Sign backing and the selected file
operation then exist before any producer facts arrive. Scoped
`append_publication` stages committed source values with their actual producer
Boot time. Partial chunks refuse admission without losing their contents;
duplicates remain idempotent, and cancellation closes further append/admission.
The complete fixed-cardinality chunk enters the same checked publication Fore.
Only the ordinary storage completion and Back commit advance its observer.

CPU conformance exercises this path with real immutable files, zero Rust allocator
calls during append/publication, and an independent read owner reopening exact
source content. Producer authentication, clock coordinates, resource placement
and grants are explicit fixtures. The native worker/Line, real Body admission,
and rolling generations/catalog checkpoint are not established by this proof.

The joint CPU native-worker/file proof includes the default 960-reading workset
in fifteen prepared 64-sample file kernels, plus a two-reading cancellation case.
Intermediate sink acceptance means bounded staging; durable acceptance advances
only at an actual chunk publication commit. All 960 readings reopen with their
quantity values, sequences and synthetic producer-minute coordinates after sink
drop. The complete workset drains naturally; the shorter case stops explicitly
and follows ordinary retirement.
With `installed-recording-proof`, the same native facts continue through the
existing catalog publication and durable Body State Source. A fresh-Boot read
view recovers the exact seed and ordered chunk references. This exercises target
worker and installed Host code with inert providers; the cross-Host Line, time
coordinates, actual Body admission and store grants remain fixtures. Only the
native sample phase has a zero-allocation measurement. Complete checkpoint
backing, an overnight rolling lifetime and physical deployment remain unproven.
