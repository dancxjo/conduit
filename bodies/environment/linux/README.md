# Linux recorder preparation

`PreparedFileRecovery` owns one ordinary production recording kernel and its
prepared Linux snapshot executor. It services the kernel's original Host Call
requests against an already opened directory; recovered history becomes visible
only through ordinary kernel steps. Preparation checks exact fragment lowering
and Play identity before transferring retained software owners.

Root must obtain the current Play from its retained, started Body binding before
each step or file service. The helper checks identity equality; identity data is
not an authority token. Root still admits live capabilities, directory custody,
capacity, and the complete memory closure. Cancellation uses the retained exact
reservation scope after the running Play loan ends.

Run `cargo xtask prove environment recording-files`. The Linux file tests include
the production kernel, a retained CPU Body lifecycle binding, foreign-scope
refusals, successful recovery, malformed content, missing files, and allocation
checks during execution. Those recovery checks do not establish a boot service,
live Host admission, MCU Line, live recording writer or overnight operation.

The runtime's `PreparedRecordingKernelFace` projects this owner's read-only
kernel through `refresh_single`. Root retains the matching kernel/Face pair and
current Body custody. The browser's existing public projector name aliases this
same implementation; both Masks consume committed recovery state.

`PreparedFileBatchRecovery<N, C>` retains the existing ordinary batch kernel and
one exact file executor per selected read (at most 16). All file preparations
precede transfer of the supplied retained software owners. Each original kernel
request routes by its selected node; a foreign Play refuses before dequeue or
Step. The complete kernel and executor memory closure still needs Root admission.

The same public file proof now includes actual publication, directory reopen,
and recovery of 1, 15 and 16 full chunks, with canonical quantities and explicit
checksum failures. Execution allocates no Rust heap. A missing middle generation
refuses without extending history beyond the preceding committed prefix. Store
offers, independent grants and producer authentication are CPU fixtures; the
test supplies the selected references and does not establish durable catalog-seed
custody or a live overnight appliance.

`PreparedFileCatalogRecovery` retains an exact snapshot reader and the shared
bounded catalogue validator during preparation. It returns decoded catalogue
access only after actual file/envelope and domain validation under independent
current read authority. Missing files, foreign authority and malformed catalogues
return no references. Reading allocates no heap; subsequent owned-reference
and ordinary batch Source preparation may allocate. Root separately admits all
memory, chunk placements, capacity and authority. The catalogue reference itself
still comes from Root; this helper does not recover the Body seed, authenticate
producer membership, acknowledge writes or create committed history.

The file proof now publishes a real 1-, 15- or 16-entry catalogue after successful
chunk file publications, reopens the directory, reads it under a fresh Boot,
and plans batch recovery from its validated references. The starting reference,
resource bindings and grants are fixtures. Separate refusal cases cover missing
files, foreign Boot authority and valid JSON with the wrong domain schema.

The optional `installed-seed` feature supplies `recover_durable_catalog_seed`.
Root passes the actual Body/residence, current std Host and sealed read-only
seed fragment. The entrance requires one bounded Body-lived ResourceRef? State
and its sole Current Fore, runs the existing installed kernel without write
inputs, retains one delivery and requests an attributed ordinary stop. It decodes
the optional reference only after successful execution and an accepted stop
receipt, preserving empty State as None and refusing bad type/profile/encoding.
This prepares later catalogue discovery; it creates no snapshot authority or
resident controller. Enabling it pulls in the existing std Host; default file
recovery stays independent of that dependency.

`cargo xtask prove environment catalog-restart` checks empty State, writing the
catalogue reference through ordinary State, a new Host/Boot recovering it and
using that actual emitted reference to read a real catalogue file. Read-only
recovery preserves the seed file bytes; truncation refuses without repair, and
a writable view refuses before State file effects. Body admission, the seed's
initial update and snapshot grants are fixtures. This test uses separate Host
instances in one process; the earlier catalog-residence proof separately checks
process separation. Publication-to-seed ordering remains the separate checkpoint
proof, and this is not an end-to-end recording or power-loss claim.


`PreparedFileRecordingPublication` owns one ordinary checked/lowered publication
kernel, the initialized recording Back and sealed encoder, and the existing exact
file executor. The authored publication view exposes JSON input and ResourceRef
output. Existing sealed Fore lowering supplies ingress/egress; no new source
scheduler or completion queue is introduced. Root obtains each current Play from
its actual Body owner, independently admits the complete memory/storage closure,
and retains directory and current provider/authority custody.

The writer admits the owned encoder once, services only original kernel requests
and exposes the Back's actual observer. A completed file effect does not advance
that observer until its ordinary completion Step commits. Local Fore consumption
preserves the checked reference and uses bounded storage; no peer or Line delivery
is implied. Both fixed event and Fore correlation Sign budgets are prepared.

The public recording-files proof includes successful publication, occupied names,
cancellation between file effect and Back commit, independent file reopen under
a new Boot, incomplete-encoder refusal before transfer, foreign-Play fencing and
zero-allocation execution. Actual successful observers feed the checked catalogue
checkpoint preparation; refused or cancelled publication cannot do so. Host/Body
admission, authenticated producer context and storage grants are fixtures. The
resident writer and live MCU ingress remain work. The combined proof below
connects the actual file and durable-State paths.


`recording_publication_offer` describes this implementation for one independently
selected durable snapshot resource. It is not readiness, a reservation or a grant:
Root must retain the actual generation and directory before advertising it.
Preparation requires this exact profile, implementation and artifact; a sealed
Plan selecting a foreign publisher refuses before generation transfer or effects.

The Linux `cargo xtask prove environment recording-checkpoint` proof writes 15
64-sample chunks through the publication kernel, gates catalogue preparation on
actual committed observers, executes the authored catalogue checkpoint through
installed std snapshot and Body-durable State, then recovers under a new
Host/Boot using the seed returned by State. A refused occupied later catalogue
preserves the prior seed. Catalogue discovery supplies the batch kernel's
references; all 960 logical samples recover from actual files. Host instances
share a process, and admission, authenticated producer identity, grants and
full capacity are fixtures. This is not live ingress, an elapsed overnight run,
a process-crash proof or an installed resident appliance.

`PreparedFileRecordingPublication::prepare_face` binds a read-only publication
Face to that writer's actual commit observer and exact checked Source/Plan/Play.
Prepare it before admitting the chunk; Root supplies each current Body Play loan
to `refresh`. A caller cannot supply a committed range or replace the observer.
The Face starts at `not-committed`, which means no commit has been observed, not
that work is active. File completion alone, occupied generations and cancellation
before the Back's ordinary commit leave it unchanged. One actual commit exposes
that generation's sample/sequence range; repeated refresh and later cancellation
preserve the same revision and historical fact.

This is per-generation publication evidence, distinct from recovered history,
current sensor readings, catalogue/Body-State checkpointing and read authority.
The ordinary Face can feed browser or native Masks; no formatting or independent
recording store is introduced. The native worker/file CPU proof prepares all
fifteen projections before 960 publications and refreshes them without allocating
in Play. Its producer clock, cross-Host Line and Host admission remain fixtures;
this does not establish an installed Pi boot service or physical HDMI output.
