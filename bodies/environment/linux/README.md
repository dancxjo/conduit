# Linux recorder preparation

`PreparedFileRecovery` owns one ordinary production recording kernel and its
prepared Linux snapshot executor. It services the kernel's original Host Call
requests against an already opened directory; recovered history becomes visible
only through ordinary kernel steps. Preparation checks exact fragment lowering
and Play identity before transferring retained software owners.

Root must obtain the current Play from its retained, started Body binding before
each step or file service. The helper checks identity equality; identity data is
not an authority token. Root still admits live capabilities, directory custody,
capacity, and the complete memory closure. Cancellation uses the retained exact
reservation scope after the running Play loan ends.

Run `cargo xtask check recording-files`. The Linux file tests include
the checked and planned production kernel, explicit CPU identity/resource fixtures,
foreign-scope refusals before dequeue or Step, successful recovery, malformed
content, missing files, and allocation checks during execution. The running
Body-binding integration remains separate; the CPU identity fixture is not
substitute admission. This is not a boot service, live Host admission, MCU
Line, or an overnight recording claim.

`PreparedFileRecordingPublication` retains one initialized chunk encoder and
publication Back beneath an exact checked publication Fore. It completes original
kernel requests through actual file operations; only the Back's committed output
advances its observer. A completed file effect alone cannot enter the catalog.
An occupied generation refuses, and cancellation after an effect preserves the
file without inventing a commit or deleting uncertain evidence.

Root can prepare the complete file/kernel backing before samples arrive, then
stage authenticated producer publications in its fixed generation. An incomplete
chunk refuses admission without losing its samples. Producer context and clock
come from Root's independently authenticated source, not the recorder's receipt
time. The writer's current Play remains a separate identity checked before each
operation. The descriptor function advertises no readiness or storage grant by
itself.

The same check suite covers actual file publication, immutable reopening,
occupied-name refusal, cancellation before and after effects, a foreign current
Play and foreign implementation selection, and allocation-free streaming into
preallocated backing. These are actual kernel and file effects with explicit CPU
Host/Body/grant/producer fixtures. Persistent catalog-State selection, restart of
the complete recorder and live Body admission still require their own integration.

`PreparedFileBatchRecovery` executes one ordered batch recovery Plot through the
same production fixed kernel. The checked Source composes exact snapshot reads,
singleton Flows and ordinary finite concatenation. Root retains each initialized
software owner, supplies current read choices and grants, and admits the complete
closure before transferring owners into the kernel. Failed preparation leaves
the supplied advertisement unchanged; transferred owners cease to be available.

The file suite covers 15 full chunks (960 observations), the 16-chunk ceiling,
reverse read completion, missing or invalid generations and stale software/table
refusal. Recurring kernel/file service allocates nothing. Catalog discovery
separately validates the immutable file and complete domain encoding before
returning generation references; missing files, foreign read grants and malformed
catalogs return no references. The optional recording kernel selects the existing
Flow implementation; it does not add that dependency to the default runtime.
These tests retain explicit CPU Host/grant/producer fixtures.

The optional `installed-seed` feature provides `recover_durable_catalog_seed`
through the existing installed Body-durable State entrance. It accepts only the
exact read-only optional-reference view, validates the returned type and profile,
and requires an attributed accepted stop before returning the reference. A write
view refuses before file effects. This feature alone adds the hosted execution
dependency; the default file adapter does not require it.

Run `cargo +stable xtask check recording-checkpoint` for the combined journey:
15 actual chunk publications feed a checked catalog publication and durable Body
State; an occupied successor preserves the previous seed; a separate process
discovers the seed and catalog and recovers all 960 observations through one
ordered batch Plot. The child receives storage paths, not a catalog reference,
and must return an explicit recovery receipt. Host/Body admission, independent
storage grants and authenticated producer context remain fixtures. This does not
establish power-loss durability or an installed live overnight recorder.
