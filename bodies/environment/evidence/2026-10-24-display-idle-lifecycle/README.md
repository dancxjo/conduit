# Physical display task release and retirement

The supported `cargo xtask prove environment display-output esp32-readiness
--flash --run-idle` entrance completed against the ESP32 and its actual retained
TM1637 owner. Fresh Body admission pinned the Boot key. The retained host Body
owner verified signed Start, Release, Cancel and Retire acknowledgements before
attributing lifecycle transitions; read-only inspection observed `waiting-input`.

The actual task advanced five kernel steps with zero software calls and zero
native calls. No Frame was submitted. Cancellation returned current terminal
progress, no cleanup failure, revoked native custody and zero operations in
flight. Only then did the host record ordinary Body Lull. Retire acknowledged
released kernel/context backing and returned native custody. The Body was not
claimed installed, and no physical display delivery or climate sampling is
claimed by this experiment. Signed transition receipts are not image attestation
or signed per-step execution evidence.

This proves physical idle execution and authenticated cleanup, extending the
adjacent dormant-preparation evidence. It does not prove admitted Frame ingress,
Mask/Look execution, active display calls, concurrent sensing, complete active
memory/stack admission or a continuing appliance. The linked stack floor remains
28 KiB; this run does not measure stack high water.

The wrapper restored the saved operational ELF after the experiment. After
flushing UART input it observed twelve current, fresh updates with acknowledged
display writes across three new sensor sequences. The recovery receipt records
the exact restored image digest. HTTP and human visual checks were not repeated.

Small lifecycle, Body and recovery receipts are retained here. The hash manifest
identifies the full ignored-target capture, firmware, UART, admission and wrapper
artifacts. Private owner key material is neither copied nor included.
