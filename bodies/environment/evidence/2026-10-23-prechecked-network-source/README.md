# Checked network meaning on ESP32

The ordinary checker and expander run during the trusted firmware build. The
4,347-byte flat image retains the exact checked graph and Source provenance;
it carries no Host, Boot, credentials, compiler-owned construction scope or Plan.
The ordinary planner produces the identical Plan from the decoded graph in the
CPU fixture. Host allocation measurements are feasibility evidence, not MCU
reservation or admission evidence.

The flashed Root loaded and retained this graph, then returned four complete
UART offers after DHCP and HTTP listeners started. The Source identity and pool
usage are in the receipt. No credential was submitted and no join, Body birth,
native Plan or kernel installation occurred. The diagnostic Boot was retired
when the working temperature/RH display firmware was restored. Offers here are
historical evidence and must not be reused for planning.

The local output directory retains both firmware artifacts and full flash and
restoration logs. Serial display acknowledgements verify protocol exchange;
they are not a human observation of illuminated LEDs.
