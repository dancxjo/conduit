# Ordinary sampler Type extents

The nine-slot sampler profile retains two 2,274-byte slots and tightens its seven
ordinary slots from 1,024 to 573 bytes, saving 3,157 payload bytes. The build checks
the maximum complete canonical extent of every independently checked protocol
Type against its class, plus the native Tick extent. Quantity-bearing observation
and result Types retain the larger class. No semantic Type, Form, queue count,
pressure policy or native authority changes. Changing the graph still requires
renewing its slot/liveness proof; this is not combined lifetime allocation.

The public publication proof passes 21 tests. The exact native worker/recorder CPU
proof passes 17 tests, including 960 source readings through fifteen actual file
generations and catalog/Body State recovery. Sensor failures, cancellation and
store refusal remain explicit. These executions retain their existing clock,
Line and admission fixtures. Strict scoped lint and the keyed ESP32 release link
pass. Full logs, ELF and map are retained outside Cargo output under
`outputs/environment-sampling-ordinary-extents`.

This image has not been flashed. Payload savings are not a measurement of actual
MCU allocator savings or stack high-water. Root/SDK heap capacities and linked
stack floor are unchanged; source acquisition time and combined sampling,
display/network admission remain unresolved. The preceding physical heap capture
belongs to its earlier source/profile and must not be relabeled as this result.
