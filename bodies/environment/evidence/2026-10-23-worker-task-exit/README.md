# Native worker task exit: resumed physical evidence

The image identified in `owner-root-image.json` booted and completed ambient
admission/capability capture. The original public owner-run command then exited
1 before Body planning or staging: concurrent snapshot-codec dependency metadata
had made the host Make lockfile stale. No Body had started at that failure.

After correcting dependency metadata, the retained capture and admission were
resumed through the existing observed-offers executable, assignment ingress and
owner-run carrier. The same Boot completed without reflashing. The original
public command did not pass end-to-end; `run-provenance.json` records that refusal,
the successful internal resumption, log digests and the actual planning binary.
The codec extraction changes neither the flashed MCU code nor the retained owner
or carrier sources. The source/image identity remains the original clean image.

The retained owner verified three signed observations, projected three Body
Faces, verified Quiesced, performed ordinary Lull and verified Retired. Start and
Release report `task_active=true`; Quiesced and Retired report false. Both terminal
reports retain the 3,472-byte static task-pool reservation; retirement reports
zero execution-context bytes and actual returned provider attachments. Final
Root heap use is 9,984 bytes, with a 105,464-byte Boot peak inside the unchanged
114,688-byte reservation. Task exit does not claim to reclaim static RAM.

The third canonical publication, its complete reply metadata apart from duplicate
payload bytes, and its Body Face are retained here. Length/digest and actual task
state were checked; full original captures of all three observations remain in
the local proof output. Admission retains the verified Boot key. This does not
prove task-slot reinstallation, another Play, owner-loss recovery, a network
transition, physical display delivery or overnight recording. Refs #6337.
