# Body proposal from current physical admission

`cargo xtask prove environment body-construction-esp32` passes on the attended
ESP32 Boot. It first performs ordinary physical Host admission, captures current
native/software offers and Root policy, and prepares the sensor workload with
the ordinary Planner. The same retained local Body evidence then enters the
ordinary lifecycle proposal, retaining the exact rich Plot Plan in AwaitingPlan.
The signed-admission observation must exactly match current native Root facts;
a stale-Boot capture refuses before Body proposal/evidence output.

The rich owner/proposal is host-side preparation evidence. The proof producer
exits after retaining these snapshots; it does not leave a running coordinator
or make an Awake snapshot restartable without normal reconciliation. No MCU
Body installation, native possession, attributed start, kernel execution or
Mask realization is claimed. The empty proposed Mask topology reflects the
absence of ready display/browser Mask owners in the current Root. Authored wear
requests remain construction inputs requiring their own realization admission.

The files are trusted local output of this invocation, not an arbitrary remote
biography or flags accepted as authentication. Admission observations retain the
actual signature exchange and matching Body identity. Full public Root replies
and rich proposal are gzip-compressed to avoid duplicating large generated
Plan/program text; captures.json pins uncompressed hashes and sizes. No secret
credentials are included. Strict example Clippy passes. No firmware changed.
