# Native offer withdrawal: physical evidence

The supported `cargo xtask prove environment owner-run-esp32` completed on the
clean source and image identified in `owner-root-image.json`. Native preparation
advanced current offer generation from 1 to 2. Start, Release, three signed
one-minute DHT observations, quiescence and retirement all retained the admitted
reservation generation 1. The actual owner projected three ordinary Body Faces,
performed ordinary Lull after verified quiescence, and verified retirement.

During sampling an internal private fixture submitted generated credentials for
an absent network. HTTP returned 202; each observation reported
`awaiting-native-retirement`. Only after retirement did the queued first attempt
run. The same Boot restored its AP after association rejection, with exactly
one credential read and one join, no station success receipt, and final offer
generation 4. The restored `/network` page returned HTTP 200.

Final Root heap use was 15,444 bytes, with a 105,592-byte Boot peak within the
114,688-byte reservation. No guard or workspace bound was relaxed. This proves
retained owner control across changed availability and queued setup ordering;
it does not prove a successful LAN join, repeatable configuration, second native
Play, browser membership, Pi output or overnight recording. The finite worker
is retired after this proof. Refs #6345, #6340 and #6341.

Each observation metadata file preserves the original reply except its duplicate
publication byte array. Exact canonical bytes are retained separately and checked
against the signed snapshot length and SHA-256. The original reply digest is
recorded. Body Face JSON is compacted without changing semantic content.
