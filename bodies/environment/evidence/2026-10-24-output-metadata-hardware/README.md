# Physical output preparation after metadata retirement

The public display-output readiness/flash/prepare proof accepted an
authenticated owner Prepare on the actual ESP32. The dormant ordinary output
kernel retained its selected native custody and an Embassy task in ready-held
state. No Start, Release or Frame was sent; software/native calls and Steps
remained zero. This is preparation evidence, not physical output execution.

Root retained 60,596 of 114,688 bytes and peaked at 92,780, leaving 21,908 bytes
at that peak. The earlier binding-first capture retained 97,872 and peaked at
105,460. Intervening changes make that comparison non-isolated: the entire
37,276-byte retained reduction is not attributed solely to metadata retirement.
The linked stack is 32,332 bytes against an unchanged 28 KiB profile floor;
neither figure measures stack high-water use. All existing guards remain.

This result does not admit combined sampling, a timed Mask or its local output
caller, networking transitions or recording. The next memory proof must cover
their actual simultaneous lifetime, rather than adding isolated high-water
figures or treating this headroom as permission to start them.

Full image, linker map, owner admission and UART captures are preserved outside
Cargo output trees at the paths hashed in curation.json. The operational
full-flash backup was restored successfully. After flushing UART input, twelve
fresh/current available observations with acknowledged display updates across
source sequences 1–3 verified recovery. HTTP and human visual inspection were
not repeated.
