# Indexed Make offers during native preparation

The existing indexed planner can now borrow complete native Host facts and a
stable, complete Make software-offer set. It reconstructs one software offer at
a time, retains only necessary selection evidence, and moves selected fields
into the same ordinary Plan construction and admission path. It does not build
an eager software catalogue beside initialized software and checked Source.

The unsafe Make interface requires deterministic complete descriptions for the
whole borrow, including defaults, laws, realization properties and limits. It
is not an incoming-wire decoder or evidence of readiness. The environmental
adapter borrows ReadyResidentOffers and its initialized owner; Root still
supplies actual native providers, resources, grants, Host, Boot and generation.
Native and software descriptions are never published as a truncated public
advertisement. No grant or memory limit is enlarged.

- All 97 planner unit tests and four indexed-offer integration tests passed.
- Complete Plan/fragment identity, current Base facts, finite resource/refusal,
  language evidence, numerical certificates, Quantity-wire backtracking and
  checked authoring Fore parity are covered. Composite count overflow refuses
  before any decoder is called.
- Strict all-target Clippy passed with default and indexed-source features.
- The generated actual sampler uses its real ReadyResidentOffers adapter and
  preserves complete Plan and missing-authority refusal equality. Preparation
  peak is 66,302 bytes versus 69,302 with an eager linked catalogue. Both retain
  54,033 bytes of selected Plan metadata. Each measurement includes one native
  descriptor clone; eager software construction is inside its measured scope.
- A deliberately broad synthetic fixture with 16 large unused definitions
  measures selection peak 404,436 versus 30,861 bytes, counting one native clone
  in each boundary. This is not the actual thermometer's memory result.

These allocator figures exclude pre-existing Source/initialized owner storage,
stack and actual target overhead. The thermometer selects almost every offer,
so selected Plan metadata remains the dominant cost. Target flash/preparation
cost, physical startup overlap and Root workspace custody still need separate
qualification. This change proves no worker ingress, protected Line, Body
membership, durable history commitment or physical execution.
