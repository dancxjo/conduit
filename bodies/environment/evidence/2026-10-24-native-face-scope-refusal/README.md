# Physical native Face scope refusal

The actual ESP32 accepted Boot admission and the paced assignment, then
authenticated native preparation refused `face-scope` while decoding Body/Wake
IDs. The task did not register or start and no sensor observation was requested.
The carrier's later owner-frame error was EOF after this explicit refusal.
Root retained 101,640 bytes and peaked at 102,152 of 114,688; Face preparation
did not complete, so this does not prove its allocation allowance.

The bounded borrowed-string deserializer did not implement the derived
newtype deserialization contract. The correction frames each previously
authenticated 64-hex ID in a 66-byte stack JSON string and uses its ordinary
Deserialize implementation, without creating lifecycle authority. A regression
exercises the actual MCU helper against both opaque Body/Wake types and rejects
wrong length, non-hex, quotation and Unicode inputs. Native re-verification of
the correction remains required.

The wrapper restored the privately retained full-flash bench backup. Flushed
UART capture verifies twelve fresh acknowledged display updates across new
sequences 1–3. Full diagnostic image, linker map and captures are preserved
outside Cargo targets under outputs/environment-native-face-probe/1792839261.
This is pre-start refusal evidence, not native Face execution or physical Mask
delivery.
