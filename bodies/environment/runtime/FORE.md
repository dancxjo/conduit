# Constrained local fore tables

The explicit `AssignedKernelTables::prepare_with_fore` and
`prepare_records_with_fore` entrances admit schema-7 local external fore records
against an independently trusted Make layout, computation inventory and exact
fore pins. The old preparation entrances continue to refuse this schema.

Both representations enter the same Core validator and fixed table builder.
They preserve cord ordinals, direction, pressure, capacities, startup order and
output routes. A local external fore uses the kernel's existing boundary endpoint
representation; no network line, peer, membership or authority is created.
Returned tables own their numeric execution material after assignment bytes and
borrowed record descriptors are dropped. Table preparation and kernel Play
allocate nothing in the fixed-store proof; Back/evaluator preparation has its
own separate storage admission.

Root must separately retain and enforce each checked value contract, authorize
submissions, admit implementation storage/work and bind any actual native Host
Calls. An ABI match grants none of these. Continuous sensor/Mask composition and
physical TM1637 execution remain separate acceptance requirements of #6378.

`cargo xtask prove environment kernel` includes the checked-Source local fore
regression: both preparation representations, resident-pin mismatch refusals,
two successive ordinary-kernel values, queue pressure, output acknowledgement,
drain and cancellation. The pure implementation offer is an explicit CPU fixture;
this proof establishes no physical provider availability.
