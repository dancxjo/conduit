# Authored source identity and complete lowering

Status: C3 normative persisted-source contract

Panel source, resolved selection, lowered semantic topology, exact plans,
runtime evidence, and presentation are separate identities. The current
pre-release source-AST and lowered-source schema marker is `0`; no other
Conduit-owned draft schema is accepted.

## Authored source identity

`semantic_source_hash` hashes the normalized authored AST under the
`conduit.panel-source` domain. It includes every authored semantic fact and
excludes comments, trivia, spans, and caller-selected root state.

Authored `root` declarations remain semantic source. Selecting one of them is
resolved input. Parsing the same source with `alpha` and `beta` selected
therefore yields:

- equal authored-source identity;
- distinct resolved root-selection identity; and
- distinct lowered identity.

For a document with one declared root, automatic selection and explicit
selection of that same target have the same semantic selection identity. Their
selection mode remains explanatory metadata.

## Complete lowered closure

`lower_source` produces one `LoweredSource` containing:

- the source-AST and lowered-source schema marker `0`;
- a content-addressed selected-root input, when one exists;
- every node path, exact contract, validated or defaulted configuration, and
  unresolved implementation or capability constraint;
- every ordinary top-level or composite cord and its complete finite flow
  policy;
- every composite-to-child ownership relationship;
- every explicit boundary export and parameter-to-child configuration binding;
- every finite port-group member and replicated-pool specification; and
- a separate source map for all those facts and relationships.

Cord endpoints, export targets, and binding targets are fully scoped semantic
paths. Their identities include the relationship kind and every plan-relevant
field. Node identities include the presence and exact value of unresolved
constraints. Whole-closure identity uses the `conduit.lowered-source` domain
over sorted typed fact hashes.

Lowering performs no implementation selection, host observation, artifact
resolution, queue allocation, provisioning, or execution. An unresolved
constraint such as `using ready` remains explicit for exact planning.

## Provenance

Imports, roots, definitions, nodes, constraints, cords, exports, and bindings
retain exact one-based source spans. Each lowered relationship maps to a
`SourceOrigin` containing:

- canonical module URI;
- exact `sha256:` module-content identity; and
- authored span.

Content identity and spans are provenance, not semantic topology. Sources that
differ only in trivia have different module-content identities but equal
authored-source and lowered identities.

## Validation and diagnostics

Only schema marker `0` is current. A different source-AST or lowered-source
marker fails as `CND-SRC-011` or `CND-LWR-011`; it is never reinterpreted or
passed to a compatibility reader. Repository-owned data is regenerated by
parsing and lowering its current source.

Dangling parameter bindings fail as `CND-SRC-003`. Inaccessible or dangling
child and export endpoints, plus boundary bypass, fail as `CND-SRC-009`.

## Conformance

`conformance/c3/source-lowering.json` is normative. It covers independent
authored and selected-root identities, implicit and explicit selection
normalization, trivia, constraints, cords, composite ownership, exports,
bindings, nested imports, exact content-identified origins, rejected schema
markers, dangling relationships, and boundary bypass.

## Normative requirements

| ID | Obligation |
|---|---|
| SRC-LWR-001 | Exclude caller-selected root state from authored source identity |
| SRC-LWR-002 | Carry selected root as explicit content-addressed resolved input |
| SRC-LWR-003 | Normalize equivalent implicit and explicit root selection |
| SRC-LWR-004 | Retain every unresolved node constraint without resolving it |
| SRC-LWR-005 | Retain every ordinary cord and complete finite flow policy |
| SRC-LWR-006 | Retain child, export, and configuration-binding relationships |
| SRC-LWR-007 | Make every plan-relevant topology change alter lowered identity |
| SRC-LWR-008 | Keep module content identity and spans in separate provenance |
| SRC-LWR-009 | Retain finite port-group and pool facts |
| SRC-LWR-010 | Accept only the one current source and lowering schema |
