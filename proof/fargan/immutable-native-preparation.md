# Exact native-profile preparation admission

The opt-in ConduitOS `fargan-native-profile-preparation` module prepares the
archived 958-placement FARGAN native-profile factory. It pins the complete
39,352,307-byte Plan, 304,884-byte literal Source, eleven full declaration files,
and all three original f32/compact/manifest resources by exact length and SHA256.
These are narrow immutable-profile inputs, not generalized FARGAN geometry.

Before hashing, decoding or checking, the entrance admits 320 MiB requested
preparation storage, 96 MiB preparation peak, and a separate 64 MiB reservation
for the already constructed full original input owners. Any one-under ceiling
refuses without allocation. Foreign bytes refuse before parsing/checking. The
original input Arcs and model resources remain in the opaque prepared owner;
the returned receipt has borrowed scalar accessors and no public constructor.

The reviewed reservation is scoped to the exact tested SDK/compiler/program.
It is not a generic Source/checker/verifier bound or a live allocator quota.
Changing the implementation/SDK requires revalidation before carrying this
profile into a concrete driver. Inputs must already be owned: their initial
file loading/Arc construction preparation is upstream and separately admitted.
Allocator bookkeeping, stack and complete runtime working storage are excluded.

Standalone actual coherent SDK tests passed all three cases (full preparation,
three one-under refusals, four foreign-input refusals), plus Clippy `-D warnings`.
Full preparation requested 258,221,149 bytes, peaked at 89,012,212 bytes and retained
44,625,188 bytes. Existing input owners retained 43,872,832 bytes (43,872,503 bytes
of original payload), under the separately admitted 64 MiB reservation. Initial
input construction itself requested 87,749,871 bytes/peaked at 78,704,635 bytes;
that measurement does not admit the upstream construction.

The full target package has not been built here: its unrelated Language Source
generation was deliberately avoided. The checked target-file implementation was
compiled directly against the pinned coherent AI/Core/Plot/Data library graph.
Integration tests require `CONDUIT_FARGAN_PREPARATION_SOURCE_ROOT` and
`CONDUIT_FARGAN_PREPARATION_ARTIFACT_ROOT` pointing to those exact archived inputs.
Evidence is in `outputs/fargan-immutable-native-preparation` of the goal project.

This admission covers native-profile preparation only. Other factories, complete
runtime storage/resources, whole public trained execution, and #5218 overlap and
attended-contrast acceptance remain separate requirements.
