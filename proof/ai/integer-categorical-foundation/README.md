# Bounded integer categorical inference foundation

This extraction adds domain-independent integer categorical scoring, immutable
model-resource custody, and an ordinary resource-admitted Kernel Step Back.
It contains no parser policy, Language Source, speech implementation, trained
weights, or public linguistic Session. Scores remain proposals to their caller.

Base: `a2fea6a2295e7ab34cfb32a9c187753e59b32585`.

Source provenance:

- `9685e19dc2af0da9a0cf60e1643f601b6ba63cf0`: integer categorical scorer and hosted adapter.
- `844f7b50818f0b5f959b4dc4e5b162117cdaca56`: immutable model resource and artifact tests.
- `ada6babe2d12dcb27cbf710bf88a1c3393c58258`: resource-admitted prepared categorical Step Back and tests.
- `20f7be78ec3cb6c6c2b0562d955e67b5df2fd149`: conservative score bound and repeated ordinary scheduler tests.

The new implementation/test files are preserved from these commits; module
exports and optional feature/dependency wiring are adapted to this base. The
`kernel-step` feature exposes the Step Back; `kernel-operation-owners` additionally
exposes its composite factory. Existing fixed-tensor/affine foundations remain
separate implementations.

The focused runtime tests cover exact adopted resources, missing/foreign/unsealed
selection, integer score parity, repeated frames after the provider is dropped,
acknowledgement-controlled progress, bounded pressure, cancellation, malformed
frames/indices, storage failure and Value/Flow completion. Passing these does not
prove whole preparation allocation bounds, linguistic quality or public Session
completion. Validation results and exact source hashes are recorded separately.

Tested source commit: `fb2ffdb591be15fceeb47ff8f0a713de4ea6c7f8`.
The following publication commit adds byte-exact logs and their hashes only;
implementation and Cargo files remain identical to that tested source.
The original missing-export diagnostic is retained separately from the ten
passing runtime tests. Preparation-wide allocation accounting remains an
inherited limitation; focused allocation-free runtime checks do not establish
a complete preparation bound.
