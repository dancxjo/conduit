## Entry and custody

PreparedFore is a concrete ticket around an existing PreparedLocalKernels observer owner and its actual borrowed native result buffer. Its safe constructor checks the complete installed Fore pin inventory one-to-one and checks the full result-buffer bound before factory construction, admission or provider binding. Pin equality proves ABI identity, not that arbitrary observer code performs typed decoding/delivery or that a carrier is authorized. The Observer remains trusted installed composition; no received observer metadata constructs it. No new unsafe trait was added.

Backing comes from the observer owner's existing checked retained_backing_bytes report, wrapper overhead and actual result span. Unknown backing or checked-arithmetic failure refuses cold. Existing with_services includes those real service loans and charges their backing within the unchanged whole-workset ceiling. The ticket's sole existing unsafe trait implementation delegates effect-free binding to that original observer owner only after complete authenticated Start.

The production admit helper uses the existing exact factory and whole resource ledger. It returns the original CommittedLocalWorkset. The start helper delegates to that original owner's authenticated Start, preserving original current-command/resource checks and repeated-Start refusal. Bound services expose observer/result loans to the existing native Runner; no second scheduler, loop, automatic frame, input policy, carrier or autonomous Start is created. Software inventory and observations remain independently installed/funded caller material.
