# Native collection Face admission

The local zero-Body Crèche selects Collection storage before producing its first
Face. Both its forwarding Plot and its configured native Mask have matching
256 KiB Fores and initialized value storage. Changing a recipe or Look preserves
that explicit profile. The existing Standard preparation entrances retain their
48 KiB limit; incoming data cannot upgrade them.

This is a finite deployment, not a universal maximum for a Face. Its supported
specimens are the complete current native catalogue and the exercised
sixteen-item Unicode inventory. A Face and each enclosing message must fit its
own bound. A byte count from a different Source revision is not admission.

## Resource ledger

| Boundary | Explicit reservation or ceiling |
| --- | --- |
| Forwarding Face value | 256 KiB, two value slots (512 KiB payload backing), separate encoded input and 256 KiB output workspace |
| Configured Mask | 256 KiB per value, ten value slots (2.5 MiB payload backing); existing bounded interaction extent remains separate |
| Renderer Host Call | One pending present, 256 KiB input and output requirements; only completed compositor custody produces an available Show |
| Private Draft/Home transfer | Version 6, 256 KiB logical blob, existing 16 KiB transfer window, at most sixteen writes; incompatible version-five envelopes refuse |
| Private service memory | Existing 1 MiB metadata grant, including 20 KiB header; allocator fit is tested independently of Root storage |
| Complete Face observer | 288 KiB, selected only with matching completed Collection producer and renderer receipts |
| Native geometry | Existing 48 commands, 192 bytes per command text, 20 rows/page, eight compositor surfaces |

The renderer receipt separately measures its exact pending present input and
completed Show result bytes. The input is checked against the complete encoded
Face; the smaller Show result is not a replacement Face measurement.

Value payload reservations exclude scheduler objects, Plans, semantic Face heaps,
serializer temporaries, and compositor surfaces. Actual producer and renderer
receipts report their backing capacities and inline objects separately. The
normal guest records Root's cumulative preparation high-water mark while the
complete observer record is retained. That measurement is not the private
service peak or a minimum-memory claim. The private-grant CPU proof runs the
production bitmap allocator in its exact admitted range.

The local Crèche does not traverse a remote owner response or WebSocket. The
existing independent Collection owner-document profile remains 384 KiB and 64
CBD1 chunks, with unchanged 48 KiB WebSocket frames. Those limits cannot be
inferred from a local Mask receipt, and this proof does not claim a new remote
collection route.

## Meaning and refusal

The producer's complete Face is retained through codec roundtrip, forwarding,
configured preparation and the native scene. Both Crèche recipes select the
checked independent collection with its sixteen-item bound. Mode, item count
and order facts come from the typed producer. Neither region limits nor item
membership are trimmed to make a specimen fit.

The reviewed selector prerequisite is retained from `9986a543c0` and
`15d21d760a`. Its legacy-facts fallback and Source identity tests remain separate
from native storage admission. Historical C1 producer measurements retain their
original Source; they are not relabeled as current-product execution.

A smaller receiver refuses before pixel effects. Overflow, malformed transfer,
stale identity and cancellation retain their existing distinct outcomes. A
larger producer cannot make a Standard Mask accept its payload. Observation
requires the same Face revision, Host/Boot/generation and renderer Plan/Play as
the acknowledged Show; stale storage receipts cannot authorize a larger record.
Configured-recipe fallback retains the complete canonical Face and reports its
reason. A capacity refusal does not retry with hidden growth.

exact canonical/linear equality, smaller-profile refusal without pixels, stale

window. Wire, decoded-byte, private-heap and RTC grants do not grow. The
sixty-four-tick allowance remains shared across Preflight, Commit and reads;
a failed entry is still quarantined rather than resumed or retried.

The full normal journey regression entrance is:

```sh

```

with `cargo xtask make host verify <OUTPUT> --journey --locked`. Actual
Application entry-cost records must establish successful complete preparation
within the existing operation allowance. A passing Crèche controls proof alone
does not establish the later Body/Patchbay wake preparation.
