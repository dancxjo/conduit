# One numerical child across ordinary Fore Values

`plots/quantity-projection/main.conduit` selects a bounded authored Each over a
Quantity-to-NearQuantity transform. `conduit run` drives it through an ordinary
stdin Fore, the installed Std Host, an exact Source/Plan and one sealed Body.
The child uses the existing installed `math/near` Back and physical allowance;
no private fixture, model weights or alternate numerical scheduler is involved.
The already persistent outer Body is not new optimization credit.

## Ownership and acceptance

The profile admits at most 64 Values, one pure Near Gear and two finite child
Value Fores, without internal cords, effects, shared pools, nested activations or
fusions. Source-selected child numerical offers and the matching parent offer
publish as one Host preparation batch. Exact Kind/configuration/Type/law,
Host/Boot/generation, Plan and subordinate preparation receipts gate installation.

One explicitly reusable child retains its installed code, numerical strategy,
encoding storage and immutable bindings. All finite child Play identities and
fresh mandatory Sign logs are reserved before Play. Old evidence and its remote
lifecycle sidecars move intact into retained per-invocation custody. An unused
future reservation does not become a reported execution. Unsupported reuse
refuses; it does not construct a replacement kernel after input arrives.

The Fore admits canonical Quantity bytes and permits one issued input obligation.
It verifies the output receipt against that exact input digest and sealed physical
limit before acknowledging Fore delivery. Child output acceptance occurs through
the parent output Step; wrong sequence ACKs and pressure cannot advance to the
next Value. Subordinate retirement yields rather than claiming a parent port
transaction. No transport epoch or unrelated network session is reset.

Malformed input, item exhaustion, Stop, stale/substituted identity, physical
refusal and output pressure remain distinct. The caller can finish and retain
terminal/child evidence after an execution refusal. Startup waits for the exact
finite preparation result, including channel closure on worker failure; machine
speed is not an arbitrary pre-Play deadline.

## Matched owner observation

The reference changes only the numerical Each installer back to the finite pool
of 64 complete children. Both policies use the same actual product preparation
routine and numerical Fore. Each worker settles process/thread initialization,
then constructs the entire Source/Host/Plan/Body owner, executes 32 `0.3m` Values,
finishes/materializes its report, inspects evidence and drops the report and
caller Source. The global allocator includes caller and Body worker threads.

The retained JSON pins both sources and workers, phase counts, raw per-call
elapsed times and two alternating reference/candidate observations. It also
retains the earlier excluded boundaries: an observer that dropped Source too
soon, and the reference startup deadline refusal. They are not successful matched
owner records.

The saving avoids preparing unused complete numerical children. Existing Source
and catalogue preparation still occurs once in both owners, and the warm caller
allocation count is similar. Warm/finish phase boundaries overlap asynchronous
child retirement; the small repeat variation is retained rather than replaced
with a fixed-cost claim. Requested bytes include allocation/reallocation
requests, not just surviving memory. Tracked heap excludes stacks, allocator and
OS internals. Payload bytes are boundary lengths, not a measurement of every
internal memory copy. Elapsed times are instrumented local dev/test observations,
not calibrated release latency or a portable speed guarantee. This does not claim
FARGAN adoption, model-weight reuse, RSS or shared main/release publication.

## Local checks

cargo xtask check plots run --deterministic --plot quantity-projection
cargo test -p conduit --bin conduit numerical_run::tests
cargo test -p conduit --test numerical_owner_cost observe_numerical_owner -- \
  --ignored --nocapture --test-threads=1

The authored consumer tests cover all 64 Values plus refused exhaustion, empty
close, malformed input without spending a reservation, producer pressure and
close, Stop retaining accepted evidence, substituted Plan/replacement Host, wrong
child output ACK and physical refusal. Native CLI reports include original
Source/Plan/Body/Play and complete child event/remote lifecycle evidence.
