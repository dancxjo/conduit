# Naming layout acceptance controls

Prepared on frozen host-proof source `f84297730828ecc3f4b480a1b7dcd53f62bf87d1` for #6158. This branch changes only CPU test code; no layout or guest observation state, limits, image configuration, or owner branch is changed. The #6205 owner's four layout files are untouched.

Existing actual Crèche tests check the first naming row against adjacent panels at 1280×800, and Unicode editing at both real extents. They do not assert the complete actual help/action/current-value group at both extents. Existing generic field-cluster tests already exercise row, height, command pressure and oversized continuation; those are reused, not duplicated. The held #6205 naming-continuation regression uses synthetic 1280×1200 geometry and does not substitute for these actual-extent assertions.

The new two tests construct the real installed four-Plot BirthDraft, select its actual Welsh catalogue member, then set a valid 64-byte Unicode friendly name. They use the real Face projection and normal authored ResponsiveColumns configuration, plus generic preparation separately. At 1280×800 and 640×480 they require the actual naming help, action and current value to remain on one page and in one lane; this short field is not excused as an oversized cluster. Complete primary/Details wording, subject associations and ordered control references must survive wrapping. Actual frame hit references must retain the original typed action/argument. The Face remains unchanged.

Per-page diagnostics retain actual row subject/control/text/bounds/panel geometry, rows, rendered commands, command payload bytes/max bytes, unique panel surfaces, chrome extent and spare space below the last row. Both primary and Details are enumerated. Literal 48-command, 192-byte per command, 20-row and eight-panel-surface ceilings are asserted. Aggregate payload bytes are diagnostic, not a new page byte limit. These observations support a concrete explanation of sparse pages with finite costs and whole-group geometry; they do not prove global whitespace optimality or invent a guest row receipt. Existing oversized-field controls own honest continuation where a field genuinely exceeds a fresh-page budget.

## Execution boundary

No Cargo command, compilation, test, QEMU run or cache write has been performed for this preparation. Standalone rustfmt and git whitespace checks only. A baseline failure is a retained regression result, not permission to weaken assertions. After explicit cache handoff, run the `naming_acceptance_tests` filter with the same hosted-tools/native-compositor profile used by the existing native scene suite and one test thread, retaining `--nocapture` output. Run existing field-cluster, actual Crèche and naming-navigation controls alongside it on the final combined source. Source-pinned normal configured before/after PNGs and visual grouping/continuation review remain separate requirements. Generic CPU preparation is not normal fallback execution. This branch does not close #6158.
