# Suppress ineligible ready membership during pending Host calls

Input, space and terminal notifications previously republished a ready bit while a Back awaited a Host completion and did not accept input during that wait. Selection rejected it later, so every idle poll revisited those blocked candidates. The ready-publication helper now consults the existing per-node Host index. Canonical queued input and terminal state remain retained; completion publishes a fresh wake. Backs that accept input during pending calls remain eligible. No scheduler field, priority rule or allocation is added.

The source-pinned fixture uses 256 real remote ingress queues and Host requests, retains one queued value per blocked node, refuses a subsequent value under pressure, completes node 255, consumes the retained input, rearms its request, and cancels with drained value/request ownership. It never seeds pending tables or ready flags. Three independent release processes per source retain exact full Sign, remote, driver-count and terminal replay. Eight idle polls go from 2,048 candidate/index probes to zero, and ready-byte probes from 2,048 to 40; allocations and reallocations stay zero.

Mean wake-publication window changes from 12,209 ns to 12,700 ns; mean eight-poll idle window changes from 15,540 ns to 331 ns. These are descriptive instrumented shared-host samples, with process variation and raw resource logs retained. The wake window includes real ingress, pressure refusal, values and mandatory Signs. This cancellation fixture has no useful output and makes no whole-Host or FARGAN throughput claim.

The independent existing 1/8/32/256-node loaded/sparse captures retain 192 cases per source, exact semantic replay, unchanged allocation/copy counters and unchanged instrumented scheduler sizes. Timing ratios vary from 0.60 to 0.82 on this uncontrolled host; they do not establish a causal common-case speedup. Preparation and fixture advance are separate raw fields.
