## Work, evidence and resources

The full call includes reservation, Back preparation, kernel Play and retained
Sign/report translation. Cold parser/checker/expansion, Host preparation,
selection and Plan sealing are measured separately. The first-to-last window
covers 63 additional real acknowledgements including collector work. Internal
phase markers and four allocation intervals remain in every current row.
Artifact serialization between phases is excluded from the cold-plus-call sum.

Logical invocations remain 1040 at depth eight and 4160 at depth 32, including
polls and terminal work. Physical decisions fall to 130 and 194; useful checked
additions remain 512 and 2048. Canonical fusion retains all intermediate
canonical materializations: 448/3584 bytes and 1984/15872 bytes respectively.
Native fusion substitutes 448/1984 native-word transports, retaining the boundary
codecs and exact outputs. These are exact fixture-derived work counts, not
hardware traffic or instrumented copy counts. Internal-copy counters remain
explicitly unavailable; no measured per-copy latency is inferred.

Native representation also has a cost: admitted Value arena capacity is
17 slots/408 bytes at depth eight and 65 slots/1560 bytes at depth 32, versus
17/136 and 65/520 for canonical profiles. Each profile's before/after capacity
is unchanged during Play. These are Value arena bounds, not total process
memory. Full calls still allocate during preparation/reporting: the first
depth-32 observations record 9330 allocations unfused, 13488 canonical fused and
12497 native fused. No whole-call zero-allocation or RSS reduction is claimed.

All 64 output acknowledgements and ordered required lifecycle identities match.
Canonical/native fused retained Sign sequences match exactly, including node,
port, request and sequence. Logical Gear/port/configuration/semantic-contract/
source-span and Cord graphs match across profiles. Original exact U64 arithmetic,
precision, overflow, pressure, cancellation and failure obligations remain in
the existing runtime conformance tests; all 28 optimized worker tests passed.
No runtime code, bounds or semantic eligibility changed in this closeout.
