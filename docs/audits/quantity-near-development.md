# Physical numerical boundary: development checkpoint

This is an unfinished development implementation under #5392/#5534. It is not stable acceptance, the proposed Fore grammar, or completion of the parent numerical corpus.

`math/near(limit=0.0001m)` consumes the actual existing Quantity wire value at an explicit boundary. The installed std profile selects either exact rational preservation or a bounded, integer-only, single-round binary32 projection. Exact and approximate outputs use the same distinct `NearQuantity` evidence record. No lossy result implicitly becomes an exact Quantity. Zero tolerance offers only the exact profile. The exact original native Quantity configuration is bound into realization properties, so a different gear's tolerance cannot authorize an offer.

The record retains the actual source wire, exact source coordinate, Unit and role, requested physical tolerance, effective coordinate tolerance, error claim and target representation. Its source-wire digest is representation custody, not mathematical identity across Units, Source document identity or execution attestation. The producer checks the existing general projection Domain/Policy report. Actual kernel Signs and the enclosing report retain execution custody separately; the Back does not fabricate Plan or Play identities.

Core's prepared borrowed verifier validates the registered schema, source wire and optional independently retained digest, source coordinate/Unit/role, effective original allowance, recomputed target and numerical error, and the consumer's actual physical tolerance. Canonical serialization alone is insufficient. Verification can only return its private-field verified result after these checks. Exact extraction additionally requires zero error. Stronger physical consumer bounds cannot be inferred from a policy-class name or relabelled certificate.

All encoder buffers and verifier schema storage are allocated during preparation. The numerical worker has a fixed work meter, and the admitted budget includes separate finite validation/composition work. Prepared state is boxed before Play to keep the shared installed Back driver small enough for ordinary thread stacks. Runtime evaluation, encoding and verification have a guarded zero-allocation test for both profiles; this is distinct from the kernel's own allocation metric.
