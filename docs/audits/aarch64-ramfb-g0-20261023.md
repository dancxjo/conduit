# AArch64 ramfb machine probe · 23 October 2026

For #6057, this G0 diagnostic identifies the next display-admission boundary. It is not a successful graphical product proof.

The preserved normal PROFILE-built AArch64 image from `fb7ee51338ccd3052851c1213ca1dc518369ed03` booted on QEMU 10.2.1 Ubuntu `1:10.2.1+ds-1ubuntu3.3`, machine `virt`, CPU `neoverse-n2`, one vCPU and 512 MiB RAM, with `-device ramfb`. Its ISO and kernel hashes match the retained build manifest. This is a historical image, not execution of the current development binary.

The guest emitted its source-backed **serial** Face, then refused with `CONDUIT_AARCH64_PRODUCT_REFUSAL observatory-framebuffer-unrepresented`. QMP captured an 800 × 600 image containing one black color. No graphical Face or acknowledged graphical Show was established. The blank capture is retained as negative evidence and must not enter a successful product gallery.

`observatory::prepare_export` requires the observed framebuffer count to equal the supplied framebuffer representations. The ordinary AArch64 entry supplies `None`, retains a serial-only Host profile, and prepares `LinearPresenter`. These three source files are unchanged between this image source and development commit `61b3410c412eed09c62a0499514ac9e85c07e793`: `targets/conduitos/src/bin/aarch64_product.rs`, `targets/conduitos/src/boot/limine.rs`, and `targets/conduitos/profiles/conduitos-aarch64-virt.host.conduit`. This is source correspondence, not whole-binary equivalence.

## Custody and reproduction boundary

The [packet manifest](evidence/aarch64-ramfb-g0-20261023/manifest.json) hashes the raw serial log, QMP receipt, exact launch command, PNG, historical build manifest and package custody. Ubuntu package bytes were checked against the selected local APT index SHA-256 and sizes, then extracted into an owned workspace directory; no system package or firmware was overwritten. The package receipt records versions and repository filenames. Runtime shared-library identities were not sealed, and this is not a hermetic toolchain proof.

Initial failures are retained: an overlong QMP socket path and mismatched system QEMU modules. A private short socket directory and matching extracted OpenGL/Spice modules resolved those setup failures. The corrected probe used a bounded 45-second observation, read only newline-complete serial records, captured QMP screendump, and terminated its own guest. It was an internal diagnostic based on the normal product launcher, not a new supported public command. Product-facing reproduction must enter through `cargo xtask make conduitos` when the G1 collector is admitted.
