# Optional exact Quantity coordinate transport (development)

Current development status (2026-10-18): the installed std Source chain
`1m -> /3 -> *3` now completes exactly through separate expression gears.
The same primitive Value profile exports `1/3m` through an external Fore and
consumes it in a fresh Play to produce `1/9m`. This is private development
proof, not stable acceptance or completion of #5392.

The selected `std/pure-expression-quantity-exact-hosted@1` offer seals finite
prepared node/depth, retained payload, numerical work and port capacity bounds.
Installation recomputes the offer and rejects missing, altered or downgraded
profile facts. Planner checks Cord codec compatibility and capacity before
Play. External Fores derive their codec profile from that sealed placement;
Core's ordinary native validator remains unchanged. Exact outputs reserve
1800 bytes; an exact input may independently restrict its byte envelope.
A small v2 rational fitting 788 bytes still requires explicit codec admission.
The existing 788-byte native Quantity wire encoding is unchanged.

Profile-aware Core validation checks physical family/role and bounded exact
range comparisons across decimal and rational representations. Native consumers
refuse optional rational transport distinctly. The installed Back uses the
existing Host Call boundary and kernel. Two fresh Plays report zero kernel
allocation events and stable prepared capacities; those observations do not
claim whole-process or preparation allocation freedom.

The final local validation set passes 292 tests across Core, lowering, Planner,
installed Back, Source batch, product CLI and refinement targets. Strict Clippy
passes across seven affected packages, with subsequent focused checks for the
filter-kind and bounded-input corrections. Core no-default-features and workspace
formatting pass. Full workspace/platform integration and publication remain due.

Limits remain explicit: this offer covers reviewed primitive Value arithmetic
and comparison. Identity-only, composite/nominal values, trig helpers and Flow
have not gained this profile. Alternative candidate selection is not yet
codec-aware. A true runtime-consuming numerical projection with general #4952
loss evidence, wider symbolic Quantity integration and the remaining original
parent acceptance are still open. The following sections retain earlier
component checkpoints and their historical refusals.

The existing decimal `Quantity` POD, 788-byte v1 encoding, literal elaboration
and native decoder are unchanged. Optional v2 transport uses the existing

`QuantityValueView` borrows the encoded coordinate and retains checked physical
metadata. Decimal inspection does not construct a rational; numerical

This is codec development, not Source or kernel acceptance. The generic

A separate Core profile contract distinguishes decimal-only consumers from the
optional exact coordinate profile. Exact consumers accept decimal producers;
decimal consumers cannot accept an exact producer without an explicit admitted
projection. Each profile publishes its finite maximum encoded extent. Unknown
physical Kinds and unsupported wire versions refuse before numerical decode.
The exact decoder checks generic Quantity, dimension-specific leaves and the
existing intrinsic family/role identities against the same checked Unit capsule.

Ten focused tests pass across profile admission, transport and the existing

## Selected-port wire contract and planner fence

A finite typed realization property records decimal or exact wire profiles for
specific input/output ports. Its fixed structured schema, sorted unique entries
and 32-port combined limit provide one canonical domain encoding. Missing ports
and missing properties retain decimal-only support. The property grants no
physical conversion, Unit binding, numerical projection or runtime authority.

Ordinary checked and expanded planning decode these facts from selected Backs,
refuse ports absent from the selected Fore, and check Payload Cords before
sealing a Plan. An exact producer connected to a decimal-only selected input
returns `quantity/wire-profile-mismatch@1` with all four endpoints. Non-payload
terminal/control tracks do not borrow the payload codec contract. Existing
realization-property fingerprinting retains the facts in the Plan. Refusal
endpoint storage is boxed on this pre-Play error path to keep common planner
error values small.

All 77 Planner library tests and nine focused Core tests pass, including ordinary
planning refusal for a nonexistent declared port, port-local eligibility, native
defaults, malformed domain codes, canonical round trips and finite bounds. Strict

The Std Source offers do not advertise this optional contract yet; the generic

## Explicit prepared exact-coordinate profile

`PreparedPortableExpressionEvaluator::new_with_exact_quantities` admits a finite
primitive-port profile explicitly. Existing constructors retain decimal policy.
The exact profile preallocates 1800-byte Quantity result buffers, propagates its
policy through input and per-node physical validation, and compares native and
rational coordinate representations by physical meaning. Native/native decimal
comparison preserves its existing path. No runtime profile fallback occurs.

The constructor checks the portable decoder's node/depth bounds and rejects
composite/nominal ports, structured intermediates, and Quantity semantic helpers
whose codecs are still decimal-only. For example, ordinary native Angle trig
remains supported by its existing profile, while this new profile refuses it
during preparation. It does not falsely promise rational input support for that
helper. Explicit input byte envelopes continue to limit accepted values.

Thirty-nine selected tests pass, including five new exact-profile cases, all five
existing authored prefix/profile cases, quantity arithmetic/context/transport,
and fourteen scalar-tape regressions. Independent prepared divide/multiply/
comparison instances execute 128 exact-third restoration cycles with zero
allocations/reallocations and stable output pointers/capacities. A coordinate
over 500 digits executes only with a sufficient declared input envelope. Strict
Plot lint and workspace formatting pass.

This constructor is not a Std offer or Source/Plan/Play acceptance. Std still
selects its decimal evaluator. The generic primitive/structured kernel validator
remains decimal-only, and Source/Fore transport ceilings, truthful selected-port
properties, resource/work facts, installed Back verification and compatible
candidate selection still need integration. No existing parent requirement is
redefined around this primitive subset; the authored wire gates remain open.
