# Face, checked component recipes and visual expression

Issue #5364 owns this separation. The initial implementation is under development;
source checking, actual native/browser rendering and acknowledged occurrence proof
must all be established before claiming the complete vertical.

## Ownership

Face (`Face` in the existing Rust API) owns subjects, exact relationships,
semantic order, names, availability, disclosure and typed source actions. Todo's
accepted model/scan remains the sole owner of its item state and transitions.

An ordinary checked component Plot owns fixed semantic slots, structural groups,
original action references, meaningful/focus traversal and admitted reflow limits.
The component recipe is source-authored canonical startup configuration. Its
selected renderer consumes that configuration from the actual planned placement;
a copied Fore hash or handwritten parallel semantic tree is insufficient.

`VisualExpression` is the initial finite visual Look facet, not a new multimodal
Look language. Density, palette, text scale and restrained motion are independent
expression preferences. The closed schema cannot carry semantic selectors,
actions, argument contracts, labels, role overrides, keyboard bindings, focus
order or component topology. #5368 owns the common optional multimodal facets;
#5377 owns declaration syntax. Neither is presumed implemented here.

The selected Mask/Host owns resource realization, platform accessibility,
measurement, geometry and actual Show acknowledgement. User accessibility and
hard Host limits outrank authored expression. Structured value bounds alone do
not establish readable geometry or reachable controls.

## Checked source and realization boundary

The ordinary Mask Fore stays `face: Face` in, `show: Show` and closing
`interaction: FaceInteraction` out. The component embeds its recipe and exposes
only a typed expression startup parameter. Changing expression may change the
expanded Plot, selected Mask Plan, Mask Play and Show. The component's original
checked source/Fore and recipe remain identical, as does the unchanged owner
Face and Todo Play/state.

The shared preparation gate must inspect the actual checked document, expansion
provenance and canonical configuration; verify the immutable selected Plan and
placement; admit the recipe and expression; and derive traversal from original
Face references. The gate independently reproduces checked expansion and the ordinary Plan using retained actual Host offers, placement choices and bounded Fore limits. It follows compiler-owned ancestor segments, including names containing slashes, and the admitted checked Back definitions. The literal recipe belongs to the exact expression-only checked component; later steps must explicitly forward its recipe and expression parameters. Stable component source/Fore evidence is separate from its changing invocation occurrence. Plan reconstruction is not a resource reservation or Show acknowledgement.

Native/browser realizations retain the original semantic references, relationships,
composition and disclosure constraints while preserving each admitted Mask's
existing reading and keyboard traversal. The private aural projection is not a
universal renderer order. Source grouping cannot reorder an interleaved control
sequence or make unmatched meaning unreachable.

Choosing different Backs of the same rendering Kind preserves the checked
component contract. Choosing different compile-time Plot/Kind parameters can
change checked specialization identity and must be recorded honestly.

## Replacement and failure

A Look-only replacement retires the prior Mask Show and reseals its route,
without Lull/Wake, workload replacement or Todo reducer restart. It renders the
same exact Face revision and acknowledges the actual new DOM/scanout occurrence.
Old Show return interactions refuse before source command admission.

Invalid visual encoding/version/identity/text scale selects the finite Phosphor
fallback request, with the refusal recorded in `VisualExpressionOutcome`.
Accessibility constraints are then applied to the fallback too and retained in an independent override record, so fallback does not hide user requirements. Unsupported
requested text scale falls back if a usable user-respecting scale exists.
Structural recipe capacity failure selects the original generic/linear projection
with user constraints retained. If that generic realization also cannot satisfy
actual text or rendering capacity, the Host refuses and does not acknowledge a
usable Show; it does not hide meaning or claim successful styling. Malformed
expression fallback applies at the visual wire admission boundary and does not
admit forged checked source. Actual DOM/native execution must prove reachable
fallback and truthful refusal paths before complete acceptance.

Look/recipe/Host identity and accepted/fallback outcome belong to realization
evidence bound to the actual acknowledged Show. They do not enter Face identity.
Focus, scroll and decorative motion may remain Mask-local; they cannot dispatch
new domain actions. Optional detail must remain genuinely reachable.

## Canonical Look and retirement

`LookInfo`, checked from `semantics/face/look.conduit`, is the finite common
contract with separately typed optional visual, spoken and generative facets.
The built-in Phosphor resource has identity `conduit.look/phosphor@1` and version
1. The visual facet carries bounded RGB/metric tokens and a checked expression;
structural breakpoint/grid selection stays with the component/Mask.

The former `ApplicationTheme` binary versions and Phosphor identities are
retired. There is no old reader or alias. Canonical admission rejects retired
identities; the browser binding requires the exact Native type profile and
reports a canonical-Look-required refusal for legacy bytes. A retained negative
fixture was checked against the old encoder before its removal.

Native CSS preparation and the browser nucleus consume the same canonical data.
The JavaScript binding decodes the existing Native structured encoding, with a
Rust conformance test pinning its complete type profile, Source digest and
actual Phosphor value. It does not define another Look wire. Unsupported or
absent facets cannot be reported as rendered. User accessibility and actual
Host constraints continue to outrank author expression; acknowledgement remains
with the selected Mask's actual Show, separately from data admission.

Facet selection is explicit: unknown requests return `Unsupported`; a missing
facet returns `Absent` even when the Host lacks that modality; an existing facet
on an unsupported Host returns `HostUnavailable`; only an existing supported
facet returns `Selected`. This is data availability, not a provider acquisition
or an acknowledged output. Spoken and generative facets are bounded policy data;
they do not yet configure a speech or generative provider.

Visual precedence reuses existing admission: user constraints and hard Host
limits outrank the requested expression. Successful fallback retains both the
requested Look and the selected canonical Phosphor resource. An impossible
user/Host constraint combination refuses. Generic no-Look browser realization
clears only paint properties owned by the previous Look and its metadata, while
preserving Face meaning and unrelated renderer properties.

## Required proof

Palette enum admission is not contrast certification or keyboard proof. The structured startup carrier and custody fixtures do not establish structural recipe interpretation or production renderer consumption.

The first application reference is unchanged accepted Todo source, one actual
Body/owner Play and Face, and the same source-checked component under Compact
and Spacious. Compare semantic identities, action arguments/availability,
relationships/order/disclosure, traversal and source basis. Then exercise a real
typed command through the current acknowledged Show. Admit maximum item/text
bounds without hidden storage growth, missing required content or unreachable
input. Prove unknown valid meaning through truthful generic fallback.

This first reference does not waive the second independent structural recipe,
dramatically different Looks, contrast/forced-colors/reduced-motion/large-text/
keyboard proof, compatibility migration or supported native/browser execution.
Deterministic admission tests, actual renderer execution, emulator/native and
physical/human evidence remain different proof classes.

The current reference document is
`semantics/face/components/todo-mask.conduit`. Its Compact and Spacious
roots invoke the same checked component with separate finite structured visual
values; Flat and Grouped are independent source-owned recipes. The production
browser offer plans this exact document through the ordinary planner and runs
the configured placement/source gate before binding owner carrier Lines. The
browser renderer re-admits the source and complete selected placements against
its current Host advertisement and the route's finite Fore budgets. The owner
route seal continues to own external Line admission; local reconstruction is
neither a resource reservation nor a replacement for the seal.

Recipe subject-region assignments retain original Face indices, including
unmatched subjects. They do not establish a universal traversal: the existing
browser collection disclosure and native document traversal remain renderer
policy constrained by the original relationships, composition, disclosures and
action contracts. The aural projection retained during recipe preparation is
only that reader's projection. A valid Face which exceeds aural clause capacity
is reported as a reading-capacity failure, distinct from invalid semantic input,
and the browser component records a generic realization fallback explicitly.

These source and renderer joins remain under development. Checked source roots,
placement reconstruction, styles, and scene options alone are not evidence of
successful native scanout, actual browser acknowledgement, stale-return refusal,
or complete issue acceptance.

## Native face entrance

In the local Crèche, F6 toggles compact/spacious spacing and F7 toggles the
engineering/editorial palette independently. Each request selects one of four
finite checked Source expressions over the same Crèche component recipe and
Face. The replacement is prepared before the previous Show retires; its new
layout restores an unsubmitted draft and exact focus only for the identical
Face and producer scope, before publishing the fresh Show. These preference
keys do not submit a Face interaction or create/advance a Body. The same four
expression combinations are available to the checked Todo component preparer.
Selection diagnostics retain the expression, component provenance, canonical
recipe hash, exact old/new Show identifiers and bounded render counts, joined
to the complete Face/Show publication records.

The native owner window exposes F6 (Compact/Flat), F7 (Spacious/Flat), F8
(Spacious/Grouped), and F9 (100%/200% minimum text size). Shift+F6 toggles
density and Shift+F7 toggles palette independently, preserving the current
recipe. Native owner selection uses four closed checked-Source preset names:
`compact`, `spacious`, `compact-editorial`, and `spacious-phosphor`; the first
two keep their existing meanings. This selector does not extend the visual
declaration language or the browser selector. These are Mask-local
requests through the current authenticated, acknowledged Show; they do not add
Face actions or alter Todo commands. The owner returns the same exact Face and
an independently sealed configured Mask route. The guest retires its previous
surface, prepares the exact returned Plan against its current observed Host
offer, renders, and acknowledges the new Show before enabling input. A failed
or uncertain exchange retires the return route. The transport retains its
explicit lifetime and finite replacement bound independently of the action
budget. An available but unacknowledged Show cannot authorize a replacement,
and the previous Show becomes stale after selection. The replacement restores
unsubmitted draft and focus only through the identical-Face and producer-scope
encounter checks used by local selection.

The native palette and font rasterizer consume the retained admitted expression.
Text measurement and glyph coverage use the same bounded scale; structural
capacity refusal records a reason and selects the original generic one-column
semantic projection at that user-respecting scale. This entrance and fallback
remain subject to actual native execution and maximum-bound journey proof; their
source implementation is not that proof.
