# Semantic effect inference

Checked composition uses the existing reviewed Kind laws for eight independent
properties: external effects, temporal state, time dependence, random dependence,
resource dependence, suspension, variability and replay. Authored Plots do not
gain a `pure` promise or an annotation that can strengthen those laws.

`ExpandedCanonicalPlot::infer_semantic_effects` accepts the actual checked
document and profile catalogue. It validates the graph and compares every field
with a fresh ordinary compiler expansion. This comparison matters: expanded
identity alone does not authenticate attached semantic-law metadata. The returned
read-only receipt borrows the exact graph and retains each primitive Gear's
original nested Plot path, source span, Kind identity and independent facts.
Core's existing fact parser supplies the laws; there is no second effect engine.

Each leaf's `knowledge` retains a separate known, missing or duplicate result
for every axis. For example, an unknown external-effect law does not erase a
known retained-state or ambient-randomness law, and replay contracts retain
their exact keys. Core's `semantic_work_knowledge` and checked contract
`work_knowledge` use that same parser. The existing complete-fact, purity and
transformation APIs still require every law exactly once; partial knowledge
cannot admit an otherwise unknown computation. Duplicate laws remain unknown
even if a later third law repeats the original value.

`summary` retains the distinct observed values of each axis. It does not order
transactional, idempotent or compensatable replay contracts, discard their keys,
or convert them to exact replay. `require_pure_expression` checks every leaf
against Core's existing semantic expression rule. A refusal names the exact
leaf and original source span. Missing and duplicate laws remain refusals,
including when another leaf has complete pure facts.

Checked `keep` declarations independently establish retained temporal state.
Each leaf exposes its borrowed `retained_declaration` and `temporal_state`,
including when its other Kind laws remain unknown. For a KEEP leaf, a pure-context
check reports the known temporal-state reason before its missing laws; complete
summaries still require every other law. Repeated template uses retain separate expanded Gear identities
while borrowing the same declaration. A matching Kind name alone establishes
no KEEP ownership. These are declaration facts, not current runtime values or
State authority. The receipt borrows both the graph and checked document.

Deferred activation bodies and shared-pool members require additional selected
body coverage. Their currently unresolved status refuses composition-wide
summary/purity conclusions; inspected owner facts do not imply knowledge of
their future work. The caller supplies a finite retained-item ceiling. Compiler
preparation keeps its own work and storage rules, and inference does not change
any existing Plan or Play limit.

Run the focused conformance entrance:

```sh
cargo xtask check semantic-effects
```

The suite combines Core law/Back conformance, checked nested Source and refusal
tests, and the existing local-expression child-kernel fixture. The latter
consumes [the authored nested specimen](../../targets/std/tests/fixtures/derived_effects.conduit)
through ordinary planning and the production local expression Back. It checks
the Source/checked/expanded identities retained in the Plan, actual input/output,
and Host Call signs. An incompatible offered effect contract is rejected by
ordinary realization matching before a replacement Plan can execute.

Semantic facts are neither execution authority nor hostile-code confinement.
Host/Boot, selected Back, resource grants and Host Call eligibility retain their
separate admission checks. A different pure computation Back may use the generic
Host Call boundary; inference alone makes no no-Host-Call claim about it. The
local child proof's zero-Host-Call and measured allocation assertions apply to
that actual prepared local profile, not every Host or primitive implementation.
Software execution, accepted publication and physical effects remain distinct
proof classes. #4070 owns the implementation and acceptance follow-through.
