# #5201 Todo kernel implementation audit (2026-10-07)

**Status:** scoped implementation audit for review; this is not accepted architecture or a capability claim.

This is an implementation of existing canon, not a proposed new invariant. The canon already requires one execution kernel, ordinary Plot-owned state and Face contributions, action/Show correlation, explicit resource persistence, and separate Body/Host identities. A direct owner-side Todo reducer or `body/todo-state.json` would add a second runtime truth path and is outside this design.

## Present seams

- `plots/todo/main.conduit` provides bounded pure `todo/command-snapshot`, summary, snapshot and restore Fores. #5202 adds generic keyed JSON operations for stable IDs and idempotent completion values. Neither an input event source nor a storage gear is wired into the Todo application Plot.
- `targets/std/src/installed_std/json_collection_tests.rs` and `targets/browser/runtime/src/plot_runner/json_tests.rs` execute the authored Todo through the production kernel, but their source and sink are `conduit-test/json-*` fixtures. They manually put the previous output into the next request; they do not retain one running Body.
- `semantics/presentation/src/face.rs` has `FaceContribution` and `PresentationFragment`, but `face/validation.rs` accepts a contribution only while its exact Plan is Playing and its active Play is current. `products/conduit/src/body_owner/controller.rs::local_face_snapshot` passes no contributions. A lulled Todo Face needs an admitted retained-state projection contract, not a fabricated active Play or owner-created application truth.
- Mask returns already carry `FaceInteraction` with an exact Face revision and acknowledged Show in `products/conduit/src/body_owner/participants/service/route.rs` and `products/conduit/src/durable_host_control/body/clock_action.rs`. They currently dispatch lifecycle/clock controls, not a bounded input to a workload Plot. No ordinary catalog Kind or installed Back transports that action into a Plot input port.
- `semantics/catalog/src/resource_snapshot.rs` defines exact-generation JSON publish/read Kinds. `targets/browser/runtime/src/plot_runner/resource_effect.rs` can suspend the existing scheduler on a resource effect and complete it after an external acknowledgement. `targets/browser/runtime/src/resource_snapshot.rs` requires `ExternalDurable` and exact planned authority. Browser conformance manually acknowledges effects. `targets/browser/host/assets/browser-resource-storage.mjs` implements bounded IndexedDB transfer but has no production caller. `targets/browser/host/assets/browser-body-host.mjs` does not handle resource effects. The installed std owner cannot use this path: `targets/std/src/hosted_resource.rs` admits only `ResourceRetention::Play`.
- Immutable `ResourceRef` publication does not name the current Todo generation. A durable current-generation pointer must be separately owned, bounded, and updated atomically with acknowledged publication. It cannot be inferred from the most recent file, browser record, Host, or Mask.

## Smallest coherent implementation order

1. Define an ordinary bounded typed interaction-ingress Kind whose planned input is the exact validated Face action occurrence and whose output is a typed Todo command. The owner authenticates the return and supplies the value to one admitted workload input; it neither applies the reducer nor chooses a storage generation. Stale Face, Show, Body, context, and item identity refuse before input delivery. Conformance first: add, complete, reopen, remove; duplicate/stale ID; pressure and cancellation.
2. Connect the ingress to `todo/state-step` within a checked Plot and keep the same active Body/Play across multiple commands. Its retained collection and sequence/ID allocation must have one exact bounded authority. Kernel output supplies snapshot and a `PresentationFragment` with list, open count, stable Item subjects/actions, and exact Plot/Plan/Play provenance. Use `FaceContribution` while Playing; explicitly define how a retained fragment remains visible during Lull without claiming a current Play.
3. Add the planned resource publish/read operation to that Plot with exact authority. First wire browser pending effects to `browser-resource-storage.mjs` and real IndexedDB acknowledgement. Then provide an installed std ExternalDurable Back or scope the first proof to a browser-owned Body; do not claim std/native portability from a browser-only Back. Admit a bounded current-generation pointer and failure atomicity; a failed publish leaves the previous generation current. Restore after Boot must validate the reference, state, Body identity, schema, and authority before exposing actions.
4. Compose the emitted fragment in owner Face projection and reseal routes after each accepted revision. All Masks consume that Face. A return through one Mask and observation through another must use the same Body ID and show the new item state without Birth.

## Reviewable issue boundary

A first prerequisite PR should establish **one admitted, bounded Face-action-to-Plot ingress and Plot-produced Face revision while Playing on one Host**, using the existing Todo reducer and production kernel. It should avoid any durability claim. This is the smallest reviewable boundary because ingress, retained collection ownership, and Face contribution are mutually necessary to prove an actual application action without a second kernel. A following persistence PR can add ExternalDurable Host effects, generation selection, Lull/Boot restore, and cross-Host realization. #5201 remains open until the human journey and Mask proofs are complete.

Candidate issue title: **Route one Todo Face action through an admitted Plot and return its current Face**

Candidate issue body:

> #5201's Todo state transition is already checked and executed by the production kernel with fixture inputs, but a live Face action cannot enter the retained Todo Plot. Add one bounded typed action ingress for add, complete, reopen, and remove. Validate the exact acknowledged Show, Face revision, interaction context, Body, and stable item target before the command enters an admitted port. The checked Todo Plot owns the collection transition and returns a bounded `PresentationFragment` with list title, open count, item identity/order/completion, and the next actions. Compose only exact current Plot/Plan/Play provenance into the owner Face and reseal Masks after the accepted revision. Prove two actions in one Body/Play through the production kernel, idempotent complete/reopen, missing and stale targets, bounded pressure, and one Mask's action observed by another. Do not claim Lull/Boot or Host-change durability in this issue; that requires a separately admitted resource and continuity vertical. No owner-side reducer, application state file, or second execution kernel.

## Proof classes and nonclaims

Deterministic kernel conformance should assert exact ports, one retained collection, output revision, failure without partial mutation, fixed capacity, and current-Show refusal. Browser proof should use pinned Chromium, one worker, zero retries; only a later storage slice can claim real IndexedDB persistence across reload/Boot. Native/ConduitOS and physical/human listening remain separate. No build or test was run for this audit.
