# Inactive cheap train input prerequisite

The default Candidate still runs the existing complete affected-package and
selected-product workflow. Exhaustive Integration is unchanged. No repository
variable or branch policy is activated by this source change.

The reviewed repository Actions variable `CONDUIT_PR_ADMISSION_TIER` must equal
`cheap-input-v1` exactly to select the alternative. Any other value, including an
unset variable, retains full Candidate. The alternative executes the actual
existing preflight: formatting, locked metadata, generated definitions,
standalone locks, repository evidence checks, the complete CI/refusal Node
corpus, actual compiled Rust workflow contract, and pinned actionlint. It defers
package admission, portable unit shards and product builds to the full combined
train. Existing preflight's small tooling/wrapper compilation is retained.

This job's success is only an input prerequisite. It cannot earn
`train-accepted`, replace exact combined Integration, publish a product, or
update `dev`. Its `conduit.candidate-cheap-input/v1` admission record preserves
run ID, run attempt, exact PR head and the complete job inventory. Only successful
`cheap-input/v1` and `candidate` jobs with the single skipped `proof` placeholder
are accepted. That exact skipped reusable-workflow job shape is a fail-closed
source contract pending a hosted observation; it is not yet hosted proof. If
GitHub emits a different inventory, admission must refuse until its actual
identity is reviewed and covered. Unknown, duplicate, missing, cancelled, failed, running, or
contradictory jobs refuse. Existing complete/native-deferred records remain
supported; their newly skipped cheap placeholder is retained as evidence.

Activation must wait for separately verified live machine-only writer and
exhaustive proof gates. A trusted controller can inject `observeCheapPolicy`
into `createTrainCommands`. Its explicit `policyApi` owner-observer channel reads
repository activation and protection; App Actions write permission is not
treated as permission to read Actions variables. The installation-token and App
JWT channels retain their narrow, separate permissions.

Every cheap selection refresh invokes that callback;
it must use `observeCheapTrainPolicy` outside PR execution to observe the actual
repository variable, dedicated App installation and exact update ruleset, plus
classic administrator-enforced `train-proof` protection with force updates
and deletion disabled. The returned grant is opaque, single-use, bounded to
60 seconds, repository-specific and never serialized into the train manifest.
A saved JSON observation or a forged callback result cannot authorize selection.
Normal trusted controller instances refuse cheap inputs when no observer is
supplied. A trusted deployment must provision and test that callback before
enabling the repository variable. The hosted `train-admit` command has a
separate read-only proof-scheduling role described below.

The observer runs from pinned, reviewed controller code outside the target
worktree and cannot load privileged code from the PR checkout. It is separate from
PR commands and source checkout execution. No App JWT, administrator token,
writer token or policy configuration is passed to the PR workflow. This
prerequisite does not provision that trusted service, register an App, change
rulesets, change required checks, or enable the variable. A controller must
refresh policy again on capture, dispatch and verification; full exact combined
product proof remains mandatory afterward.

The [trusted controller command](train-controller.md) wires the observer and
short-lived App session to explicit capture/dispatch/acquisition/landing
operations. Its existence does not activate this tier or establish live gates.

## Read-only scheduling and trusted control

Hosted `train-admit` uses `createTrainProofAdmission`, a narrow read-only API.
It checks a bounded canonical train manifest and exact clean source checkout,
observes live dev and ready PR heads plus latest Candidate run/attempt/complete
job inventories, reconstructs the exact selected Git merge tree, and reobserves
all that mutable custody after reconstruction. Structural cheap eligibility is
sufficient at this boundary: its only result is a source/tree/manifest digest
that permits scheduling exhaustive Integration. It cannot update refs, restore
accepted artifacts, adopt proof, publish or land, and has no policy-bypass flag.
The CI job uses ordinary read permissions; it receives no App JWT or owner or
writer credential.

Trusted assembly, capture, dispatch, artifact acquisition/restore, verification
and landing keep their existing fresh external machine policy requirement.
`createTrainDispatcher` accepts an explicitly supplied trusted `commands` adapter
or `observeCheapPolicy` callback, preserving fresh grants across its repeated
`prepareDispatch` calls. A read-only proof identity is never an input grant to
those methods. The trusted session adapter must remain pinned outside the target
worktree and provide this callback; it cannot turn the unprivileged scheduling
API into landing authority. Full exact combined products and server landing
gates remain mandatory even after read-only scheduling succeeds.
