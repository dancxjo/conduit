The read-only path audit now separates local Crèche admission from remote owner transport: [source-path/bounds/resource plan](https://github.com/dancxjo/conduit/blob/882fbc6b518b8903cdf03d195a3487c04a9e15c6/task-6038/work/6156-native-capacity-readonly-plan.md).

Normal zero-Body Crèche does not traverse an owner response or WebSocket. Its complete Face crosses snapshot, Mask, present Host Call and interaction admission, then the whole observer record. These are separately bounded; current Source's 64,530-byte default and 201,468-byte maximum exercised specimen are not admitted by the existing bounds.

The remote owner route already fragments logical documents using CBD1. Its 32 KiB native frame ceiling is **not** a whole-Face ceiling. The sender currently uses 8,178-byte payload frames, while semantic response/logical-document bounds and the receiver's 16-chunk cap remain distinct. At the current chunk payload, the 201,468-byte Face alone would need 25 chunks before envelope overhead. Raising only a Mask buffer or wire frame would therefore be insufficient.

The prerequisite can establish an explicit local large-Face profile while retaining and regression-checking the existing small Todo owner profile. Any actual larger remote specimen must be admitted end to end, with complete envelopes, receiver/chunk limits and reservations proved rather than inferred. The plan requires measured preparation peaks and unchanged scene budgets; old capacity-bump work is provenance, not a ready patch. No implementation, Host admission or guest proof is claimed by this audit. The #5994 serial gate remains in force.
