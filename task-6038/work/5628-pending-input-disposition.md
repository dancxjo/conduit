# Pending input during selected Look replacement

Existing behavior discarded `NativeFaceScene::InputState` by replacing `NativeFaceMask` after the owner selection round-trip. Named focus restoration alone would not recover provisional argument bytes, and no draft-preservation claim was justified.

Prepared successor behavior: `FaceArrival::ensure_look_replacement_ready` checks the current scene's actual pending input before `route.select_component`. A provisional argument action or submitted-but-unresolved occurrence refuses with `owner-look-provisional-input`. The old Mask, argument buffers, Face and Show remain in place; neither the owner request nor replacement runs. The same guard precedes text-scale/forced-color preference mutation, so refusal cannot silently change a later selection. With no pending input, the existing authenticated route proceeds and restores exact named focus before acknowledging the new Show.

`InputState::has_pending_input` reports actual retained action/submission state, including empty provisional text and binary/choice drafts; it does not infer input from displayed strings. A typed-then-erased buffer remains provisional until explicit commit/cancellation. This is refusal, not draft migration or automatic submission. Native input has no claim of browser IME composition support. The existing bounded preview was extracted intact into `native_face_scene/input/preview.rs` to keep the input reducer below 500 lines.

This is Source preparation only. Real draft/key-event regressions and owner request count/fresh Show proof remain required once the build/proof cache is handed over. No runtime acceptance is claimed by this note.

Follow-up: desired scale/forced-color preferences now stay local until replacement preparation succeeds and `self.mask = replacement` crosses the local swap boundary. Route/preparation/suspend failures before that assignment preserve prior preferences. After that boundary, presentation/focus/owner-ack failure is explicitly not treated as rollback. `select_owner_component_with_preferences` carries the proposal without mutating current preparation fields.

Submitted state is occurrence-local, not permanent: authoritative owner results with a Face call `FaceArrival::present_owner_face` → `NativeFaceMask::present_with_input` → newly prepared `NativeFaceScene`, whose `InputState` is default. Results without a Face or route failures retire the return route and present the retained Face read-only through the same fresh-scene path. Local notices alone do not clear submitted state. Explicit Escape cancels an unsubmitted draft; it cannot replay a submitted occurrence. Prepared CPU tests exercise typed/erased draft, Escape, subsequent submission and fresh-scene state. Product-level failed-request and acknowledged-refresh proof remains pending.
